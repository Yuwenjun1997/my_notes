一、Django 概览

1.1 Django 是什么

Django 是一个"大而全"的 Python Web 框架，遵循 MTV 架构模式，自带 ORM、Admin 后台、认证、迁移等一整套功能，适合快速构建功能完整的应用。

核心特点

特性说明
电池齐备（Batteries Included）认证、Admin、ORM、表单、安全一应俱全
MTV 架构Model（数据）/ Template（视图）/ View（逻辑）
自带 ORM数据库抽象层，无需 SQL
Admin 后台零代码生成数据管理界面
成熟稳定十多年沉淀，文档丰富
迁移机制模型变更自动生成数据库迁移

安装与创建项目

# 安装
pip install django

# 创建项目（项目 = 配置集合）
django-admin startproject mysite

# 创建应用（应用 = 功能模块）
cd mysite
python manage.py startapp blog

# 启动开发服务器
python manage.py runserver

1.2 项目结构

mysite/
├── manage.py              # 项目管理入口
├── mysite/                # 项目配置（settings/urls/wsgi）
│   ├── settings.py        # 全局配置
│   ├── urls.py            # 根 URL 路由
│   ├── wsgi.py            # WSGI 入口
│   └── asgi.py            # ASGI 入口
└── blog/                  # 应用（功能模块）
    ├── models.py          # 数据模型
    ├── views.py           # 视图函数
    ├── urls.py            # 应用路由
    ├── admin.py           # Admin 注册
    ├── migrations/        # 数据库迁移文件
    └── templates/         # HTML 模板

项目 vs 应用：一个项目可包含多个应用（如用户系统、订单系统、支付系统各一个应用）。

二、模型与 ORM

2.1 定义模型

Model 是数据库表的 Python 映射，每个模型类对应一张表，每个字段对应一列。

# blog/models.py
from django.db import models

class Category(models.Model):
    name = models.CharField(max_length=50, unique=True)   # 分类名

    def __str__(self):
        return self.name

class Post(models.Model):
    title = models.CharField(max_length=200)              # 标题
    content = models.TextField()                          # 正文
    category = models.ForeignKey(                          # 外键（多对一）
        Category, on_delete=models.CASCADE,
        related_name="posts",
    )
    views = models.IntegerField(default=0)                # 浏览量
    published = models.BooleanField(default=False)        # 是否发布
    created_at = models.DateTimeField(auto_now_add=True)  # 创建时间

    def __str__(self):
        return self.title

常用字段类型

字段对应数据库类型说明
CharFieldVARCHAR短文本，必须指定 max_length
TextFieldTEXT长文本
IntegerFieldINT整数
FloatField/DecimalFieldFLOAT/DECIMAL浮点/高精度小数
BooleanFieldBOOL布尔值
DateTimeFieldDATETIME日期时间
ForeignKey外键多对一
ManyToManyField关联表多对多
OneToOneField外键+唯一一对一

2.2 生成迁移

迁移（Migration） 将模型变更同步到数据库。

# 1. 生成迁移文件（根据模型变化自动生成 SQL）
python manage.py makemigrations blog

# 2. 查看将要执行的 SQL（不实际执行）
python manage.py sqlmigrate blog 0001

# 3. 执行迁移
python manage.py migrate

2.3 ORM 链式查询

ORM 提供链式查询 API，无需手写 SQL。

# blog/views.py
from django.db.models import Count, Q
from .models import Post

# 查询全部
posts = Post.objects.all()

# 过滤
published = Post.objects.filter(published=True)
high_views = Post.objects.filter(views__gt=1000)          # views > 1000
recent = Post.objects.filter(created_at__year=2026)       # 2026 年发布
search = Post.objects.filter(Q(title__icontains="python") | Q(content__icontains="python"))

# 排序与切片
top = Post.objects.order_by("-views")[:10]                # 浏览量 Top 10

# 聚合
total = Post.objects.count()
avg_views = Post.objects.aggregate(avg=Count("views"))

# 关联查询（双下划线穿透外键）
posts_in_tech = Post.objects.filter(category__name="技术")

# 排除与去重
others = Post.objects.exclude(category__name="广告").distinct()

QuerySet 是惰性的：查询只在真正取值时执行（迭代、list()、切片等），可先拼接过滤条件再执行。

三、视图与 URL

3.1 FBV（函数视图）

FBV（Function Based View） 用普通函数处理请求，简单直观。

# blog/views.py
from django.shortcuts import render, get_object_or_404
from .models import Post

def post_list(request):
    posts = Post.objects.filter(published=True).order_by("-created_at")
    # render：渲染模板并返回响应
    return render(request, "blog/post_list.html", {"posts": posts})

def post_detail(request, post_id):
    post = get_object_or_404(Post, id=post_id, published=True)  # 404 处理
    return render(request, "blog/post_detail.html", {"post": post})
# blog/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("", views.post_list, name="post_list"),          # 路径参数用 <int:post_id>
    path("post/<int:post_id>/", views.post_detail, name="post_detail"),
]
# mysite/urls.py 根路由引入应用路由
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),   # 挂载 blog 应用
]

3.2 CBV（类视图）

CBV（Class Based View） 用类封装常用逻辑，内置大量通用视图，代码复用性高。

# blog/views.py
from django.views.generic import ListView, DetailView
from .models import Post

class PostListView(ListView):                    # 列表页通用视图
    model = Post
    template_name = "blog/post_list.html"
    context_object_name = "posts"                # 模板中变量名
    paginate_by = 10                             # 每页 10 条

    def get_queryset(self):                      # 覆盖默认查询
        return Post.objects.filter(published=True).order_by("-created_at")

class PostDetailView(DetailView):                # 详情页通用视图
    model = Post
    template_name = "blog/post_detail.html"
# blog/urls.py
from django.urls import path
from .views import PostListView, PostDetailView

urlpatterns = [
    path("", PostListView.as_view(), name="post_list"),
    path("post/<int:pk>/", PostDetailView.as_view(), name="post_detail"),  # 通用视图用 pk
]

FBV vs CBV

对比维度FBVCBV
代码量简单场景更少通用场景更少
复用性低（需重复逻辑）高（继承通用视图）
可读性直观易懂需了解继承体系
适用场景简单页面标准 CRUD 页面

3.3 Django Admin 后台

Admin 是 Django 内置的数据管理后台，注册模型后即可在线管理数据。

# blog/admin.py
from django.contrib import admin
from .models import Post, Category

@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ("title", "category", "views", "published", "created_at")  # 列表列
    list_filter = ("published", "category")       # 右侧过滤
    search_fields = ("title",)                    # 搜索框
    list_editable = ("published",)                # 列表页直接编辑

访问 http://127.0.0.1:8000/admin/，用 createsuperuser 创建的管理员账号登录。

python manage.py createsuperuser

四、Django REST Framework 入门

4.1 Serializer

DRF（Django REST Framework） 是 Django 构建 REST API 的官方推荐扩展。

pip install djangorestframework
# mysite/settings.py 注册应用
INSTALLED_APPS = [
    ...
    "rest_framework",
    "blog",
]
# blog/serializers.py
from rest_framework import serializers
from .models import Post

class PostSerializer(serializers.ModelSerializer):   # 自动根据模型生成序列化器
    class Meta:
        model = Post
        fields = ["id", "title", "content", "views", "created_at"]  # 注意不含敏感字段
        read_only_fields = ["views", "created_at"]

4.2 APIView 与 ViewSet

# blog/api.py
from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status
from .models import Post
from .serializers import PostSerializer

class PostListAPI(APIView):                      # 类视图
    def get(self, request):
        posts = Post.objects.filter(published=True)
        return Response(PostSerializer(posts, many=True).data)

    def post(self, request):
        serializer = PostSerializer(data=request.data)
        if serializer.is_valid():                # 校验
            serializer.save()
            return Response(serializer.data, status=status.HTTP_201_CREATED)
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

ViewSet + Router：更简洁的 CRUD 组合，一行注册 5 个接口。

# blog/api.py
from rest_framework.viewsets import ModelViewSet
from .models import Post
from .serializers import PostSerializer

class PostViewSet(ModelViewSet):
    queryset = Post.objects.all()
    serializer_class = PostSerializer
# mysite/urls.py
from rest_framework.routers import DefaultRouter
from blog.api import PostViewSet

router = DefaultRouter()
router.register("api/posts", PostViewSet)     # 自动生成 GET/POST/PUT/DELETE 等路由

urlpatterns = [
    ...
    path("", include(router.urls)),
]

五、Django vs FastAPI 对比

5.1 选型对比

对比维度DjangoFastAPI
定位大而全（全栈框架）小而精（API 框架）
异步部分支持（3.0+，同步为主）原生异步
性能中等（同步为主）高（异步）
ORM自带（Admin 生态丰富）无（配合 SQLAlchemy/SQLModel）
数据校验Form/SerializerPydantic（类型安全）
Admin 后台✅ 内置❌ 需第三方
自动文档弱（需 drf-spectacular）✅ 内置 Swagger/ReDoc
学习曲线较陡（概念多）平缓（代码量少）
适用场景内容站、后台管理系统高性能 API、微服务

5.2 选择建议

场景推荐
内容管理系统、博客Django（Admin + 模板开箱即用）
高性能 REST APIFastAPI
微服务架构FastAPI
前后端完全分离FastAPI
需要管理后台Django
团队已有 Django 经验Django

5.3 部署要点

Django：runserver 仅用于开发，生产环境用 WSGI 服务器。

# 生产：gunicorn 运行 WSGI 应用
pip install gunicorn
gunicorn mysite.wsgi:application --bind 0.0.0.0:8000 --workers 4

# 静态文件收集（JS/CSS/图片）
python manage.py collectstatic

FastAPI：使用 uvicorn 运行 ASGI 应用（见 2.2 模块）。

六、实践项目

项目 1：用 Django Admin 管理博客数据模型

目标：创建一个博客应用，定义数据模型，用 Django Admin 完成数据管理。

步骤：

  1. 用 django-admin startproject mysite 创建项目
  2. 创建 blog 应用，定义 Category 和 Post 模型
  3. 执行 makemigrations 和 migrate
  4. 在 admin.py 注册模型并配置列表显示、过滤、搜索
  5. 创建超级用户，启动服务在 Admin 后台添加分类和文章
  6. 写一个 post_list FBV 视图，在模板中渲染文章列表
