一、存储引擎概述

MySQL 的存储引擎是插件式的，不同引擎适用于不同场景。InnoDB 是 MySQL 5.5+ 的默认引擎。

1.1 InnoDB vs MyISAM 对比

特性InnoDB（默认）MyISAM
事务支持✅ 支持 ACID❌ 不支持
行级锁✅ 支持❌ 只有表锁
外键✅ 支持❌ 不支持
崩溃恢复✅ Redo Log 保证❌ 需要手动修复
MVCC✅ 支持❌ 不支持
全文索引✅ MySQL 5.6+ 支持✅ 原生支持
聚簇索引✅ 有（主键索引即数据）❌ 没有（索引与数据分离）
存储文件.ibd（数据+索引）.MYD（数据）+ .MYI（索引）
AUTO_INCREMENT必须有索引可以没有索引
COUNT(*)需遍历（无缓存）有内部计数器，很快

结论：除非有非常明确的理由（如只读表、旧系统兼容），否则始终使用 InnoDB。

1.2 其他存储引擎简介

引擎特点适用场景
Memory数据存内存，重启丢失，支持 Hash 索引临时表、缓存表
CSV数据以 CSV 格式存储数据导入导出中间层
Archive只支持 INSERT/SELECT，高压缩日志、历史归档数据
Federated访问远程 MySQL 表跨库查询（不推荐）

二、InnoDB 架构详解

2.1 内存结构

┌─────────────────────────────────────────────────────┐
│                    InnoDB 内存结构                     │
├──────────────────────┬──────────────────────────────┤
│   Buffer Pool 缓冲池  │   Change Buffer 修改缓冲      │
│   - 数据页和索引页     │   - 非唯一二级索引的延迟写入    │
│   - 自适应 Hash 索引  │   - 减少随机 IO              │
│   - 锁信息            │                              │
├──────────────────────┴──────────────────────────────┤
│               Log Buffer 日志缓冲（Redo Log）          │
│         - 事务提交前先写 Log Buffer，再按策略刷盘      │
└─────────────────────────────────────────────────────┘

2.2 Buffer Pool 详解

Buffer Pool 是 InnoDB 最重要的内存区域，缓存数据页和索引页：

-- 查看 Buffer Pool 状态
SHOW STATUS LIKE 'Innodb_buffer_pool%';

-- 关键指标
-- Innodb_buffer_pool_read_requests  逻辑读取次数
-- Innodb_buffer_pool_reads          物理读取次数（从磁盘读取）
-- 命中率 = 1 - (reads / read_requests)  理想值 > 99%

Buffer Pool 工作原理：

  1. 查询数据时，先在 Buffer Pool 中查找
  2. 命中 → 直接返回（无磁盘 IO）
  3. 未命中 → 从磁盘读取数据页到 Buffer Pool，再返回
  4. Buffer Pool 满时，使用 LRU（最近最少使用） 算法淘汰旧页

改进的 LRU 算法：InnoDB 将 LRU 列表分为两部分：

  • young 区（热数据，约 5/8）：经常访问的页
  • old 区（冷数据，约 3/8）：新读入的页先放这里，再次被访问后才移到 young 区

这样避免了全表扫描等操作污染 Buffer Pool（大量冷数据被读入后直接把热数据挤出）。

2.3 Redo Log（重做日志）

作用：保证事务的持久性，记录数据页的物理修改，用于崩溃恢复。

事务执行流程：
BEGIN → 修改内存（Buffer Pool）→ 写 Redo Log（prepare 状态）→ COMMIT → Redo Log 刷盘（commit 状态）
                                                                      ↑
                                                     如果此时崩溃，重启后根据 Redo Log 恢复
-- Redo Log 相关参数
SHOW VARIABLES LIKE 'innodb_log%';

-- innodb_log_file_size      Redo Log 文件大小（建议 256MB-1GB）
-- innodb_log_files_in_group Redo Log 文件数量（默认 2）
-- innodb_log_buffer_size    Redo Log 缓冲区大小（默认 16MB）

-- innodb_flush_log_at_trx_commit 控制刷盘策略：
-- 0：每秒写入磁盘（可能丢失 1 秒数据）
-- 1：每次提交都刷盘（最安全，默认） ← 生产推荐
-- 2：每次提交写 OS Cache，每秒刷盘

2.4 Undo Log（回滚日志）

作用：

  1. 保证事务的原子性（支持回滚）
  2. 实现 MVCC（提供数据的历史版本）
执行 UPDATE 时：
1. 将修改前的数据写入 Undo Log（用于回滚和 MVCC）
2. 修改 Buffer Pool 中的数据页
3. 将修改后的数据写入 Redo Log（用于崩溃恢复）

回滚时：
根据 Undo Log 中的旧值，将数据恢复到修改前的状态

2.5 DoubleWrite（双写）

解决问题：防止数据页写入过程中操作系统崩溃（部分写入，partial write）。

刷盘过程：
1. 先将脏页写入 DoubleWrite Buffer（连续磁盘空间，顺序 IO）
2. 再将脏页写入实际数据文件（随机 IO）
3. 如果步骤 2 崩溃，重启后从 DoubleWrite Buffer 恢复该页

2.6 InnoDB 后台线程

线程作用
Master Thread协调各后台线程，处理刷脏、合并插入缓冲、刷新日志
Page Cleaner Thread负责脏页刷新（从 Buffer Pool 刷到磁盘）
IO Read Thread数据页读取（多个线程并行读）
IO Write Thread数据页写入（多个线程并行写）
Log ThreadRedo Log 刷盘

三、表空间管理

3.1 表空间类型

表空间类型说明
系统表空间（ibdata1）存放 InnoDB 数据字典、Change Buffer、DoubleWrite 等
独立表空间（.ibd）每个表一个文件（innodb_file_per_table=ON，默认开启）
通用表空间自定义表空间，多个表共享
Undo 表空间存放 Undo Log
临时表空间存放临时表数据

3.2 独立表空间管理

-- 查看表空间文件
SHOW VARIABLES LIKE 'innodb_file_per_table';  -- ON（默认开启）

-- 表空间文件位置
-- /var/lib/mysql/<database>/<table>.ibd

-- 回收表空间（删除数据后不会自动释放磁盘空间）
ALTER TABLE users ENGINE=InnoDB;  -- 重建表，回收空间

-- MySQL 8.0+：在线回收
OPTIMIZE TABLE users;  -- 等价于 ALTER TABLE ... ENGINE=InnoDB

-- 查看表空间大小
SELECT
  table_name,
  ROUND(data_length / 1024 / 1024, 2) AS data_mb,
  ROUND(index_length / 1024 / 1024, 2) AS index_mb
FROM information_schema.TABLES
WHERE table_schema = 'mydb';

四、存储引擎选择决策

你的场景是什么？
│
├─ 需要事务支持？ ──── Yes ──→ InnoDB
├─ 需要行级锁？ ───── Yes ──→ InnoDB
├─ 需要外键？ ─────── Yes ──→ InnoDB
├─ 只读历史日志表？ ── Yes ──→ Archive
├─ 临时数据（可丢失）？ Yes ──→ Memory
├─ 旧系统必须用 MyISAM？ Yes ──→ MyISAM（建议迁移）
└─ 其他 ──────────────→ InnoDB（默认选择）
