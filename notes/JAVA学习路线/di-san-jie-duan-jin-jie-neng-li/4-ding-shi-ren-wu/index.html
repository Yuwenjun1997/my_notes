一、Cron 表达式详解

Cron 表达式是定时任务的核心，由 6 或 7 个字段 组成，用于定义任务的执行时间规则。

1.1 Cron 表达式结构

┌──────── 秒 (0-59)
│ ┌────── 分 (0-59)
│ │ ┌──── 时 (0-23)
│ │ │ ┌── 日 (1-31)
│ │ │ │ ┌ 月 (1-12 或 JAN-DEC)
│ │ │ │ │ ┌ 星期 (0-7, 0 和 7 都代表周日, 或 SUN-SAT)
│ │ │ │ │ │
* * * * * *

注意：Spring @Scheduled 的 cron 表达式只有 6 位（秒 分 时 日 月 星期），而 Linux crontab 是 5 位（缺少秒字段）。Quartz 支持 7 位（可选的年份字段）。

1.2 特殊字符

字符含义示例说明
*所有值* * * * * ?每秒执行
?不指定（仅日/星期）0 0 12 ? * MON每周一 12:00，不关心日期
-范围0 0 9-18 * * ?每天 9 点到 18 点每小时执行
,枚举0 0 9,12,18 * * ?每天 9 点、12 点、18 点执行
/步长0/5 * * * * ?每 5 秒执行
LLast（最后）0 0 0 L * ?每月最后一天 0 点
W工作日0 0 0 15W * ?15 号最近的工作日
#第几个0 0 0 ? * 2#3每月第 3 个周一

1.3 常用表达式速查

// 常用 Cron 表达式一览
"0 0 0 * * ?"         // 每天 0 点
"0 0 2 * * ?"         // 每天凌晨 2 点
"0 0/5 * * * ?"      // 每 5 分钟
"0 0 0/1 * * ?"      // 每小时
"0 0 9,12,18 * * ?"  // 每天 9 点、12 点、18 点
"0 0 9-18 * * ?"     // 每天 9 点到 18 点每小时
"0 0 9 ? * MON-FRI"  // 工作日 9 点
"0 30 9 ? * MON-FRI" // 工作日 9:30
"0 0 0 1 * ?"        // 每月 1 号 0 点
"0 0 0 L * ?"        // 每月最后一天
"0 0 0 ? * 1"        // 每周日凌晨
"0 0 0 1 1 ?"        // 每年 1 月 1 日
"0 0/30 9-17 * * ?"  // 工作日 9:00-17:30 每半小时
"0 0 0 1W * ?"       // 每月 1 号最近的工作日
"0 15 10 ? * 6L"     // 每月最后一个周五 10:15
"0 15 10 ? * 6#3"    // 每月第 3 个周五 10:15

// 在线 Cron 验证工具：https://crontab.guru/
// 中文推荐：https://tool.lu/crontab/

1.4 Cron 表达式陷阱

// ❌ 错误示例
"* * 0 * * ?"        // 0 点到 0:59 每秒执行，不是每天一次!
"0 0 0 * * ? "       // 末尾多一个空格，可能导致解析失败

// ✅ 正确写法
"0 0 0 * * ?"        // 每天 0 点执行一次

// Quartz 的 cron 和 Spring 的 cron 有何不同？
// Spring Scheduled: 6 位（秒 分 时 日 月 星期）
// Quartz: 7 位（秒 分 时 日 月 星期 年），第 7 位可选
// Linux crontab: 5 位（分 时 日 月 星期）

二、Spring Task（@Scheduled）

Spring 内置的轻量级定时任务方案，适合单机简单场景。

2.1 快速入门

启用定时任务

@Configuration
@EnableScheduling  // 关键注解：开启定时任务支持
public class SchedulingConfig {
}

基本使用

@Component
public class SimpleScheduleTasks {

    // 固定延迟：上次执行完成后等待 5 秒再执行
    @Scheduled(fixedDelay = 5000)
    public void taskWithFixedDelay() {
        System.out.println("固定延迟 5 秒：" + LocalDateTime.now());
    }

    // 固定频率：每 5 秒执行一次（不考虑上次执行时间）
    @Scheduled(fixedRate = 5000)
    public void taskWithFixedRate() {
        System.out.println("固定频率 5 秒：" + LocalDateTime.now());
    }

    // 初始延迟：应用启动后等待 10 秒再开始
    @Scheduled(initialDelay = 10000, fixedDelay = 5000)
    public void taskWithInitialDelay() {
        System.out.println("启动 10 秒后开始，之后每 5 秒执行");
    }

    // Cron 表达式
    @Scheduled(cron = "0 0 2 * * ?")
    public void taskWithCron() {
        System.out.println("每天凌晨 2 点执行：" + LocalDateTime.now());
    }
}

2.2 fixedDelay vs fixedRate

fixedDelay（固定延迟）：以上次执行 *完成* 时间为基准
┌─────┐      ┌─────┐      ┌─────┐
│ 执行 │─等待─│ 执行 │─等待─│ 执行 │
└─────┘  5s  └─────┘  5s  └─────┘

fixedRate（固定频率）：以上次执行 *开始* 时间为基准
┌─────┐  ┌─────┐  ┌─────┐
│ 执行 │  │ 执行 │  │ 执行 │
└─────┘  └─────┘  └─────┘
  5s        5s        5s

fixedDelayString / fixedRateString：支持配置文件占位符
// 从配置文件读取间隔
@Scheduled(fixedDelayString = "${task.sync.fixed-delay:5000}")
public void configurableTask() {
    // 可通过 application.yml 动态调整延迟
    // task.sync.fixed-delay: 10000
}

2.3 线程池配置

默认情况下，所有 @Scheduled 方法共用 1 个线程，一个任务阻塞会影响其他任务！

@Configuration
@EnableScheduling
public class SchedulingConfig implements SchedulingConfigurer {

    @Override
    public void configureTasks(ScheduledTaskRegistrar taskRegistrar) {
        ThreadPoolTaskScheduler scheduler = new ThreadPoolTaskScheduler();

        scheduler.setPoolSize(10);                       // 线程池大小
        scheduler.setThreadNamePrefix("scheduled-");     // 线程名前缀
        scheduler.setAwaitTerminationSeconds(60);        // 关闭时等待任务完成
        scheduler.setWaitForTasksToCompleteOnShutdown(true);
        scheduler.setRejectedExecutionHandler(
            new ThreadPoolExecutor.CallerRunsPolicy());   // 拒绝策略：调用者执行

        scheduler.initialize();
        taskRegistrar.setTaskScheduler(scheduler);
    }
}
# 也可通过配置文件简单设置（Spring Boot 2.1+）
spring:
  task:
    scheduling:
      pool:
        size: 10
      thread-name-prefix: scheduled-

2.4 异步定时任务

@Component
public class AsyncScheduleTasks {

    @Async  // 异步执行，不阻塞其他任务，不阻塞调度线程
    @Scheduled(fixedDelay = 5000)
    public void asyncTask() throws InterruptedException {
        System.out.println("异步任务开始：" + Thread.currentThread().getName());
        Thread.sleep(10000);  // 模拟耗时操作
        System.out.println("异步任务结束");
    }
}

// 必须配合 @EnableAsync
@Configuration
@EnableAsync
public class AsyncConfig {
    // 也可配置异步线程池...
}

2.5 动态管理定时任务

@Component
public class DynamicScheduledTask {

    @Autowired
    private ThreadPoolTaskScheduler taskScheduler;

    private ScheduledFuture<?> future;

    // 启动任务
    public void startTask(String cron) {
        future = taskScheduler.schedule(
            () -> System.out.println("动态任务执行：" + LocalDateTime.now()),
            new CronTrigger(cron)
        );
    }

    // 停止任务
    public void stopTask() {
        if (future != null && !future.isCancelled()) {
            future.cancel(false);  // false: 不中断正在执行的任务
        }
    }

    // 修改任务（先停后启）
    public void changeTask(String newCron) {
        stopTask();
        startTask(newCron);
    }
}

2.6 Spring Task 的局限性

局限说明
单机执行多实例部署时每个实例都执行，造成重复
不支持分布式没有任务分片、故障转移机制
管理能力弱没有可视化 UI，无法手动触发/暂停
持久化缺失任务状态不持久化，重启后丢失
无重试机制任务失败不会自动重试

三、Quartz 框架

Quartz 是 Java 生态中最成熟的定时任务框架，支持集群部署和持久化。

3.1 核心概念

┌──────────────────────────────────────────────────┐
│                  Scheduler（调度器）                 │
│  ┌────────────────┐          ┌────────────────┐  │
│  │   JobDetail     │          │    Trigger     │  │
│  │  (任务定义)      │ ──关联── │   (触发器)      │  │
│  │  - JobClass     │          │  - Cron 表达式  │  │
│  │  - JobDataMap   │          │  - 开始/结束时间 │  │
│  └────────────────┘          └────────────────┘  │
└──────────────────────────────────────────────────┘

核心组件：
- Job：任务接口，实现 execute() 方法定义业务逻辑
- JobDetail：Job 的详细描述（名称、分组、附加数据）
- Trigger：触发器，定义 Job 何时执行
  - SimpleTrigger：简单触发器（间隔/重复次数）
  - CronTrigger：基于 Cron 表达式的触发器
- Scheduler：调度器，管理 Job 和 Trigger 的生命周期
- JobStore：存储 Job 和 Trigger 的状态
  - RAMJobStore（内存存储，默认）
  - JDBCJobStore（数据库存储，支持集群）

3.2 快速入门

依赖

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-quartz</artifactId>
</dependency>

定义 Job

// 方式一：实现 Job 接口
public class SimpleJob implements Job {

    @Override
    public void execute(JobExecutionContext context) throws JobExecutionException {
        JobDataMap dataMap = context.getJobDetail().getJobDataMap();
        String param = dataMap.getString("param");

        System.out.println("Job 执行中，参数: " + param
                + "，时间: " + LocalDateTime.now());
        System.out.println("Job 名称: " + context.getJobDetail().getKey());
        System.out.println("Fire 时间: " + context.getFireTime());
        System.out.println("Next Fire 时间: " + context.getNextFireTime());
    }
}

// 方式二：继承 QuartzJobBean（Spring 集成方式）
public class SpringQuartzJob extends QuartzJobBean {

    @Override
    protected void executeInternal(JobExecutionContext context)
            throws JobExecutionException {
        // 可以注入 Spring Bean
        System.out.println("Spring Quartz Job 执行");
    }
}

Quartz 配置类

@Configuration
public class QuartzConfig {

    // 1. 定义 JobDetail
    @Bean
    public JobDetail simpleJobDetail() {
        return JobBuilder.newJob(SimpleJob.class)
                .withIdentity("simpleJob", "default")     // 名称 + 分组
                .withDescription("简单定时任务")
                .usingJobData("param", "hello-quartz")    // 传递参数
                .storeDurably()                            // 无触发器时也保留
                .build();
    }

    // 2. 定义 Trigger
    @Bean
    public Trigger simpleJobTrigger() {
        return TriggerBuilder.newTrigger()
                .forJob(simpleJobDetail())                // 关联 JobDetail
                .withIdentity("simpleTrigger", "default")
                .withDescription("每 10 秒执行一次")
                .withSchedule(SimpleScheduleBuilder.simpleSchedule()
                        .withIntervalInSeconds(10)         // 每 10 秒
                        .repeatForever())                  // 无限重复
                .build();
    }

    // 3. CronTrigger 示例
    @Bean
    public JobDetail cronJobDetail() {
        return JobBuilder.newJob(SpringQuartzJob.class)
                .withIdentity("cronJob", "default")
                .build();
    }

    @Bean
    public Trigger cronJobTrigger() {
        return TriggerBuilder.newTrigger()
                .forJob(cronJobDetail())
                .withIdentity("cronTrigger", "default")
                .withSchedule(CronScheduleBuilder.cronSchedule("0 0/5 * * * ?"))
                .build();
    }
}

3.3 任务状态处理

@Configuration
public class QuartzStatefulConfig {

    // @DisallowConcurrentExecution：禁止并发执行
    // 上一个任务未完成时，下一次不会触发
    @DisallowConcurrentExecution
    public static class StatefulJob implements Job {
        @Override
        public void execute(JobExecutionContext context)
                throws JobExecutionException {
            try {
                Thread.sleep(30000);  // 模拟长任务
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
    }

    // @PersistJobDataAfterExecution：执行后持久化 JobDataMap
    @PersistJobDataAfterExecution
    @DisallowConcurrentExecution
    public static class PersistentJob implements Job {
        @Override
        public void execute(JobExecutionContext context) {
            JobDataMap dataMap = context.getJobDetail().getJobDataMap();
            int count = dataMap.getInt("count");
            count++;
            dataMap.put("count", count);  // 执行后自动持久化
        }
    }
}

3.4 Quartz 集群

# application.yml
spring:
  quartz:
    job-store-type: jdbc  # 使用数据库存储（代替默认的内存存储）
    jdbc:
      initialize-schema: always  # 自动建表（生产环境用 never）
    properties:
      org:
        quartz:
          scheduler:
            instanceName: MyClusteredScheduler
            instanceId: AUTO  # 自动生成实例 ID
          jobStore:
            class: org.quartz.impl.jdbcjobstore.JobStoreTX
            driverDelegateClass: org.quartz.impl.jdbcjobstore.StdJDBCDelegate
            isClustered: true                     # 开启集群模式
            clusterCheckinInterval: 15000         # 集群心跳间隔（ms）
            tablePrefix: QRTZ_                    # 表前缀
            misfireThreshold: 60000               # 超时阈值
          threadPool:
            class: org.quartz.simpl.SimpleThreadPool
            threadCount: 20
            threadPriority: 5
            threadsInheritContextClassLoaderOfInitializingThread: true

Quartz 数据库表结构（核心表）

-- 核心表及其作用
QRTZ_JOB_DETAILS         -- 存储 JobDetail 信息
QRTZ_TRIGGERS            -- 存储 Trigger 信息
QRTZ_CRON_TRIGGERS       -- 存储 Cron 表达式
QRTZ_SIMPLE_TRIGGERS     -- 存储简单触发器配置
QRTZ_SIMPROP_TRIGGERS    -- 存储扩展属性
QRTZ_FIRED_TRIGGERS      -- 存储正在执行的触发器
QRTZ_SCHEDULER_STATE     -- 存储调度器状态（集群节点）
QRTZ_LOCKS               -- 集群中的悲观锁
QRTZ_PAUSED_TRIGGER_GRPS -- 被暂停的触发器组

集群工作原理

               ┌──────────────┐
               │  数据库（锁）   │
               └──────┬───────┘
          ┌───────────┼───────────┐
          │           │           │
    ┌─────┴─────┐┌────┴──────┐┌───┴──────┐
    │ Node 1    ││  Node 2   ││ Node 3   │
    │ Scheduler ││ Scheduler ││ Scheduler│
    └───────────┘└───────────┘└──────────┘

集群保证：
1. 任务不会被重复执行（通过数据库行锁）
2. 节点故障自动转移（心跳检测）
3. 任务负载自动均衡

3.5 Quartz 监听器

// 任务监听器
@Component
public class MyJobListener implements JobListener {

    @Override
    public String getName() {
        return "myJobListener";
    }

    @Override
    public void jobToBeExecuted(JobExecutionContext context) {
        System.out.println("任务即将执行: " + context.getJobDetail().getKey());
    }

    @Override
    public void jobExecutionVetoed(JobExecutionContext context) {
        System.out.println("任务被拒绝执行: " + context.getJobDetail().getKey());
    }

    @Override
    public void jobWasExecuted(JobExecutionContext context, JobExecutionException e) {
        if (e != null) {
            System.out.println("任务执行异常: " + e.getMessage());
        } else {
            System.out.println("任务执行完成: " + context.getJobDetail().getKey()
                    + "，耗时: " + context.getJobRunTime() + "ms");
        }
    }
}

四、XXL-JOB 分布式任务调度

XXL-JOB 是国内使用最广泛的分布式任务调度平台，提供可视化 Web 管理界面。

4.1 架构设计

┌──────────────────────────────────────────────────────┐
│                   XXL-JOB Admin（调度中心）              │
│  ┌─────────────┐ ┌─────────────┐ ┌────────────────┐  │
│  │ 任务管理      │ │ 调度日志     │ │ 执行器管理      │  │
│  ├─────────────┤ ├─────────────┤ ├────────────────┤  │
│  │ 报表统计      │ │ 用户管理     │ │ 告警管理        │  │
│  └─────────────┘ └─────────────┘ └────────────────┘  │
└──────────────┬──────────────────┬──────────────────┘
               │  HTTP 调度请求    │
               ▼                  ▼
┌──────────────────────┐ ┌──────────────────────┐
│   Executor 1（Web 应用）│ │   Executor 2（任务应用）  │
│                       │ │                       │
│  ┌─────────────────┐ │ │  ┌─────────────────┐  │
│  │ Glue (在线编写)    │ │ │  │ Bean 模式任务     │ │
│  │ 注册的任务 Handler │ │ │  │ 注册的任务 Handler │ │
│  └─────────────────┘ │ │  └─────────────────┘  │
└──────────────────────┘ └──────────────────────┘

核心角色：
- 调度中心（Admin）：负责任务调度、管理和监控
- 执行器（Executor）：负责接收调度指令并执行任务

xxl:

    executor:

@Configuration
public class XxlJobConfig {

    @Value("${xxl.job.admin.addresses}")
    private String adminAddresses;

    @Value("${xxl.job.executor.appname}")
    private String appname;

    @Value("${xxl.job.executor.port}")
    private int port;

    @Value("${xxl.job.accessToken}")
    private String accessToken;

    @Bean
    public XxlJobSpringExecutor xxlJobExecutor() {
        XxlJobSpringExecutor executor = new XxlJobSpringExecutor();
        executor.setAdminAddresses(adminAddresses);
        executor.setAppname(appname);
        executor.setPort(port);
        executor.setAccessToken(accessToken);
        executor.setLogPath("logs/xxl-job");
        executor.setLogRetentionDays(30);
        return executor;
    }
}

4.3 开发任务 Handler

@Component
public class OrderJobHandler {

    @Autowired
    private OrderService orderService;

    /**
     * 1. BEAN 模式（常用）：基于方法的任务
     * 参数：@XxlJob 注解的值为任务名称（与调度中心配置一致）
     */
    @XxlJob("orderTimeoutCancelHandler")
    public void cancelTimeoutOrders() {
        // 获取任务参数
        String param = XxlJobHelper.getJobParam();
        int shardIndex = XxlJobHelper.getShardIndex();  // 分片索引
        int shardTotal = XxlJobHelper.getShardTotal();  // 分片总数

        XxlJobHelper.log("开始处理超时订单，分片: {}/{}",
                shardIndex, shardTotal);

        try {
            int count = orderService.cancelTimeoutOrders();
            XxlJobHelper.handleSuccess("处理完成，取消 " + count + " 个超时订单");
        } catch (Exception e) {
            XxlJobHelper.log("处理失败: " + e.getMessage());
            XxlJobHelper.handleFail("处理失败: " + e.getMessage());
        }
    }

    /**
     * 2. 定时统计任务
     */
    @XxlJob("dailyOrderStatisticsHandler")
    public void dailyStatistics() {
        try {
            // 获取昨天日期
            String yesterday = LocalDate.now().minusDays(1).toString();

            Map<String, Object> stats = orderService.statisticsByDate(yesterday);
            XxlJobHelper.log("订单统计: {}", stats);

            XxlJobHelper.handleSuccess("统计完成");
        } catch (Exception e) {
            XxlJobHelper.handleFail(e.getMessage());
        }
    }

    /**
     * 3. 分片任务：每个执行器处理一部分数据
     * 适用于大数据量的批处理任务
     */
    @XxlJob("shardingDataSyncHandler")
    public void shardingDataSync() {
        int shardIndex = XxlJobHelper.getShardIndex();
        int shardTotal = XxlJobHelper.getShardTotal();

        // 将用户 ID 按分片取模分配
        // 每台机器只处理属于自己的那一部分数据
        List<Long> userIds = userService.getUserIdsByShard(shardIndex, shardTotal);

        for (Long userId : userIds) {
            try {
                orderService.syncUserOrders(userId);
            } catch (Exception e) {
                XxlJobHelper.log("同步用户 {} 订单失败: {}", userId, e.getMessage());
            }
        }

        XxlJobHelper.handleSuccess("分片 " + shardIndex + " 同步完成");
    }
}

4.4 路由策略

策略说明适用场景
FIRST固定选择第一个执行器开发测试
LAST固定选择最后一个极少用
ROUND轮询分配通用
RANDOM随机分配简单均衡
CONSISTENT_HASH一致性哈希需要同类型任务落到同机器
LEAST_FREQUENTLY_USED最少使用负载均衡
LEAST_RECENTLY_USED最近最久未使用负载均衡
FAILOVER故障转移（心跳失败则切换）高可用
BUSYOVER忙碌转移（阻塞则切换）避免任务堆积
SHARDING_BROADCAST广播分片（所有执行器都执行）数据分片处理

Elastic-Job 是 Apache ShardingSphere 的子项目，定位为轻量级、去中心化的分布式任务调度方案。

┌──────────────────────────────────────────────────┐

// 常见的分片策略实现
public class ShardingStrategies {

    // 1. 按 ID 范围分片（适合有自增 ID 的数据）
    public static List<Range> splitByRange(int shardTotal, long maxId) {
        long shardSize = (maxId + shardTotal - 1) / shardTotal;
        List<Range> ranges = new ArrayList<>();
        for (int i = 0; i < shardTotal; i++) {
            ranges.add(new Range(i * shardSize,
                    Math.min((i + 1) * shardSize - 1, maxId)));
        }
        return ranges;
    }

    // 2. 按 ID 取模分片（适合数据均匀分布）
    public static String getModSql(int shardIndex, int shardTotal) {
        return String.format(
            "SELECT * FROM users WHERE MOD(id, %d) = %d",
            shardTotal, shardIndex
        );
    }

    // 3. 按分库分表规则分片
    public static List<DataNode> getDataNodes(int shardIndex, int shardTotal) {
        // 将数据库 + 表分配给不同分片
        // 分片 0 → db_0.db_0, db_1.table_1
        // 分片 1 → db_2.table_0, db_3.table_1
        return new ArrayList<>();
    }
}

7.3 失败重试与补偿

@Component
public class RetryableTaskHandler {

    /**
     * 常见重试策略
     */
    @XxlJob("retryableTaskHandler")
    public void execute() {
        int maxRetries = 3;
        int retryCount = 0;

        while (retryCount < maxRetries) {
            try {
                doBusiness();
                XxlJobHelper.handleSuccess();
                return;
            } catch (Exception e) {
                retryCount++;
                XxlJobHelper.log("第 {} 次重试失败: {}",
                        retryCount, e.getMessage());

                if (retryCount >= maxRetries) {
                    // 最终失败：记录到补偿表
                    saveToCompensationTable(e);
                    XxlJobHelper.handleFail("重试 " + maxRetries + " 次后仍失败");
                } else {
                    // 等待后重试（指数退避）
                    try {
                        Thread.sleep((long) Math.pow(2, retryCount) * 1000);
                    } catch (InterruptedException ie) {
                        Thread.currentThread().interrupt();
                    }
                }
            }
        }
    }

    private void doBusiness() {
        // 实际业务逻辑
    }

    private void saveToCompensationTable(Exception e) {
        // 将失败记录写入补偿表，由人工或补偿任务处理
    }
}

7.4 任务超时处理

@Component
public class TimeoutAwareTaskHandler {

    @XxlJob("timeoutTaskHandler")
    public void execute() {
        // 获取任务配置的超时时间
        long timeout = XxlJobHelper.getJobTimeout();  // 秒

        ExecutorService executor = Executors.newSingleThreadExecutor();
        Future<?> future = executor.submit(this::doLongRunningTask);

        try {
            future.get(timeout, TimeUnit.SECONDS);
            XxlJobHelper.handleSuccess();
        } catch (TimeoutException e) {
            future.cancel(true);  // 中断任务
            XxlJobHelper.handleFail("任务超时，已强制终止");
        } catch (Exception e) {
            XxlJobHelper.handleFail(e.getMessage());
        } finally {
            executor.shutdownNow();
        }
    }

    private void doLongRunningTask() {
        // 可能长时间运行的任务
    }
}

八、最佳实践

8.1 设计原则

1. 幂等性
   - 任务可能被重复触发，必须保证多次执行结果一致
   - 使用唯一标识（如订单号）做幂等校验

2. 可终止性
   - 任务应支持安全中断（检查中断标志）
   - 避免写不可中断的死循环

3. 可观测性
   - 记录每次执行的开始/结束时间
   - 记录处理数据量、成功数、失败数
   - 异常时发出告警

4. 资源隔离
   - 为定时任务配置独立的线程池
   - 避免影响正常的业务请求处理

5. 优雅停机
   - 应用关闭时等待正在执行的任务完成
   - 或持久化执行状态，下次启动恢复

8.3 常见坑与避坑指南

坑说明避坑方式
@Scheduled 单线程默认只有 1 个线程，任务阻塞影响全部配置线程池
Cron 年字段陷阱Spring 是 6 位，Quartz 是 7 位统一校验格式
集群重复执行@Scheduled 多实例都执行用分布式锁或 XXL-JOB
大事务锁表批量更新不提交导致锁等待分批提交
