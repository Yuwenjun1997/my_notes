3-文件系统与目录结构

约 2205 字大约 7 分钟

2026-08-15

一、FHS 标准目录结构

Linux 遵循 FHS（Filesystem Hierarchy Standard，文件系统层次结构标准），所有目录从根 / 开始。

1.1 核心目录一览

/
├── /bin        → 基本命令（已链接到 /usr/bin）
├── /boot       → 启动文件（内核、grub）
├── /dev        → 设备文件（硬盘、键盘、终端）
├── /etc        → 系统配置文件 ⭐ 最常用
├── /home       → 用户主目录 ⭐
│   └── /home/username/
├── /lib        → 共享库文件（已链接到 /usr/lib）
├── /media      → 自动挂载的可移动媒体
├── /mnt        → 手动临时挂载点
├── /opt        → 第三方独立软件
├── /proc       → 虚拟文件系统（进程/内核信息）
├── /root       → root 用户的主目录
├── /run        → 运行时临时文件（tmpfs，重启清空）
├── /sbin       → 系统管理命令（已链接到 /usr/sbin）
├── /srv        → 服务数据目录
├── /sys        → 内核与设备信息（虚拟）
├── /tmp        → 临时文件（重启可能清空）
├── /usr        → 用户软件与库 ⭐
│   ├── /usr/bin/      → 用户命令
│   ├── /usr/lib/      → 库文件
│   ├── /usr/local/    → 本地编译安装的软件
│   └── /usr/share/    → 共享数据（文档、图标）
└── /var        → 可变数据 ⭐
    ├── /var/log/      → 日志文件
    ├── /var/lib/      → 应用状态数据（数据库、包管理器）
    ├── /var/cache/    → 缓存
    └── /var/tmp/      → 持久化临时文件

1.2 重要目录详解

目录用途示例
/etc所有系统级配置文件/etc/ssh/sshd_config、/etc/nginx/nginx.conf
/home普通用户的家目录/home/alice/Documents
/var/log系统和应用日志/var/log/syslog、/var/log/nginx/access.log
/usr/local手动编译安装的软件/usr/local/bin/myapp
/tmp所有用户可写的临时目录建议用 /var/tmp 存重要临时文件
/opt独立第三方软件包/opt/google/chrome

⚠️ 注意事项：

  • /tmp 目录在重启后可能被清空（取决于配置），不要存放重要文件。
  • 不要随意修改 /etc 下的配置文件，修改前务必备份。
  • /proc 和 /sys 是虚拟文件系统，不要直接编辑其中的文件。

二、文件类型

Linux 中一切皆文件。使用 ls -l 第一个字符查看文件类型：

字符类型说明
-普通文件文本、二进制、图片等
d目录文件夹
l符号链接（软链接）类似 Windows 快捷方式
b块设备文件硬盘、U盘（/dev/sda）
c字符设备文件键盘、鼠标（/dev/tty）
p管道文件进程间通信
s套接字文件网络通信
$ ls -l /dev/sda
brw-rw---- 1 root disk 8, 0 Jun 22 10:00 /dev/sda
# b = 块设备

$ ls -l /etc/ssh/sshd_config
-rw-r--r-- 1 root root 2766 Jun 22 10:00 /etc/ssh/sshd_config
# - = 普通文件

$ ls -l /usr/bin/python3
lrwxrwxrwx 1 root root 10 Jun 22 10:00 /usr/bin/python3 -> python3.12
# l = 符号链接

三、inode 与链接

3.1 inode 概念

每个文件在磁盘上都有一个 inode（索引节点），存储文件的元数据：

  • 文件大小、所有者、权限
  • 时间戳（创建/修改/访问时间）
  • 数据块在磁盘上的位置
  • 不包含文件名（文件名存在目录项中）
# 查看文件的 inode 号
ls -i filename
stat filename

3.2 硬链接 vs 软链接

对比维度硬链接 (Hard Link)软链接 (Symbolic Link)
本质指向同一个 inode指向文件路径（独立 inode）
跨文件系统❌ 不可以✅ 可以
链接目录❌ 不允许✅ 可以
删除源文件链接仍可用链接失效（断链）
创建命令ln source linkln -s source link
# 硬链接：同一个 inode
$ echo "hello" > file1
$ ln file1 file2          # 创建硬链接
$ ls -li file1 file2
123456 -rw-r--r-- 2 user user 6 Jun 22 10:00 file1
123456 -rw-r--r-- 2 user user 6 Jun 22 10:00 file2
#      ↑ inode 相同                 ↑ 链接计数 = 2

# 软链接：不同 inode
$ ln -s file1 file3       # 创建软链接
$ ls -li file1 file3
123456 -rw-r--r-- 1 user user 6 Jun 22 10:00 file1
123457 lrwxrwxrwx 1 user user 5 Jun 22 10:00 file3 -> file1
#      ↑ inode 不同
硬链接原理：                      软链接原理：
┌──────────┐                    ┌──────────┐
│ 目录项A  │──→ inode #100      │ 目录项A  │──→ inode #100 (数据="hello")
│ 目录项B  │──→ inode #100      │ 目录项B  │──→ inode #101 (数据="目录项A路径")
└──────────┘                    └──────────┘
 两个名字同一个文件                 B 指向 A 的路径

四、挂载（Mount）

Linux 将所有存储设备（硬盘、U盘、光盘）挂载到统一目录树中，不像 Windows 用盘符（C:、D:）区分。

# 查看当前挂载情况
df -h                   # 人类可读格式
mount | column -t       # 详细挂载信息
lsblk                   # 列出块设备树

# 临时挂载 U 盘
sudo mount /dev/sdb1 /mnt/usb

# 卸载
sudo umount /mnt/usb

# 永久挂载（编辑 /etc/fstab）
sudo vim /etc/fstab
# UUID=xxx-xxx  /data  ext4  defaults  0  2

/etc/fstab 字段说明：

# <设备>           <挂载点>  <文件系统>  <选项>     <dump>  <fsck>
UUID=abc-123-def  /data     ext4        defaults   0       2

五、常用文件系统类型

文件系统特点适用场景
ext4Linux 默认、稳定可靠、最大 1EB通用（Ubuntu 默认）
XFS高性能、适合大文件、RHEL 默认数据库、大文件存储
Btrfs快照、压缩、写时复制（COW）高级存储管理
ZFS数据完整性校验、快照、压缩NAS、数据安全场景
NTFSWindows 默认文件系统双系统数据共享
tmpfs内存文件系统、重启丢失/tmp、/run

六、进阶：/proc、时间戳、inode 耗尽

6.1 /proc 与 /sys 实战读法

# /proc：虚拟文件系统，内核实时暴露进程/系统信息（§1.1 只提了"虚拟"）
cat /proc/meminfo | head -5         # 内存详情（MemTotal/MemAvailable）
cat /proc/loadavg                   # 1/5/15 分钟负载
cat /proc/version                   # 内核版本
cat /proc/1/status | grep -E "Name|State|Threads"   # init 进程信息
cat /proc/cpuinfo | grep "model name" | uniq         # CPU 型号

# /proc/sys：内核运行参数，与 sysctl 一一对应 ⭐
cat /proc/sys/net/ipv4/ip_forward   # 等同 sysctl net.ipv4.ip_forward
cat /proc/sys/vm/swappiness         # swap 倾向性（3.1 §6.2 / 4.3 会调它）

# /sys：设备和驱动信息（偏硬件/总线）
ls /sys/block/                      # 块设备
cat /sys/block/sda/queue/scheduler  # 磁盘调度器（4.3 §1.4 已见）

💡 echo 1 > /proc/sys/... 可临时改内核参数但重启失效；永久改要走 sysctl 配置（4.3 §三）。

6.2 atime / mtime / ctime 与 stat 全解

stat file.txt
#   Access: 2026-08-15 17:30:00  (atime)
#   Modify: 2026-08-15 17:30:00  (mtime)
#   Change: 2026-08-15 17:30:00  (ctime)
时间戳含义何时更新
atime最后访问时间cat/less 读取时
mtime最后修改时间内容被改写时
ctime元数据变化时间权限/属主/链接数变化时（不是创建时间！）

💡 ctime 不是"创建时间"，是"状态（inode 元数据）变化时间"。挂载选项 noatime 就是"不更新 atime 以提升性能"（3.1 §3.3）。排查"文件被谁改过"看 mtime，"权限何时变"看 ctime。

6.3 目录为何不能硬链接、软链接更新

# 目录不能硬链接：避免产生"目录环"（a→b→a 无限循环）
# 内核只允许 . 和 .. 这两个特例目录链接，其余一律拒绝

# 更新软链接要加 -n（否则可能把新链接建到原目录里）⭐
ln -sn /new/target linkname     # 安全地重新指向
readlink linkname               # 查看软链接指向的真实路径
ls -l linkname                  # 末尾 -> 显示指向

# 实际场景：切换 Java 版本，用软链接改默认
ln -sn /usr/lib/jvm/java-17 /opt/java-default

6.4 inode 耗尽：磁盘"满"但空间充足

# 现象：df -h 还有空间，但创建文件报 "No space left on device"
# 原因：inode 用尽（每个文件/目录都要占一个 inode）
df -i                    # ⭐ 看 IUsed/IUse%，接近 100% 就是 inode 耗尽
df -hi                   # 人类可读

# 排查谁占用了大量 inode（小文件堆积：缓存/日志轮转失败/邮件队列）
find / -xdev -type f | cut -d/ -f2 | sort | uniq -c | sort -rn | head
find /var -xdev -type f | wc -l    # 看 /var 下文件总数

# 清理方向：清空旧日志/缓存、删除海量小文件、让 logrotate 生效（3.4 §三）

💡 典型场景：应用疯狂写小日志、logrotate 没生效、/tmp 堆积。inode 与磁盘空间是两个独立维度，排查要同时看 df -h 和 df -i。

6.5 文件系统类型与挂载详情

df -T                    # 显示每列的文件系统类型 ⭐
df -hT                   # 类型 + 人类可读大小
findmnt                  # 挂载树（比 mount 更清晰）⭐
findmnt /data            # 看指定挂载点的设备/类型/选项
mount -o remount,rw /     # 重新挂载（改只读→可写，3.1 §6.1 恢复会用到）

💡 判断"能否在线扩容/缩容"、"为什么 mv 跨盘很慢"（2.2 §5.5）都要先确认文件系统类型——df -T/findmnt 是最快方式。

📝 实践项目

目标

熟悉 Linux 目录结构和文件类型。

步骤

  1. 浏览目录树

    # 用 tree 命令查看结构（需安装 tree）
sudo apt install tree -y
tree -L 2 /          # 显示两层目录结构
tree -d -L 2 /       # 只显示目录

  2. 创建链接实验

    mkdir ~/link-test && cd ~/link-test
echo "original content" > original.txt

# 创建硬链接
ln original.txt hard.txt

# 创建软链接
ln -s original.txt soft.txt

# 查看 inode 差异
ls -li

# 删除源文件，观察链接变化
rm original.txt
cat hard.txt      # ✅ 正常读取
cat soft.txt      # ❌ 报错：No such file or directory

  3. 查看磁盘挂载信息

    df -h
lsblk -f          # 显示文件系统类型和 UUID
cat /etc/fstab    # 查看永久挂载配置

  4. 查看文件 inode 信息

    stat /etc/passwd
stat /etc/hostname
