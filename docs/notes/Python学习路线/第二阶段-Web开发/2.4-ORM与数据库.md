# ORM 与数据库

## 一、数据库驱动与连接

### 1.1 Python 数据库驱动

**数据库驱动** 是 Python 与数据库通信的底层库，ORM 建立在驱动之上。

| 数据库 | 同步驱动 | 异步驱动 | 说明 |
|--------|---------|---------|------|
| **PostgreSQL** | `psycopg2` / `psycopg` | `asyncpg` | psycopg 3 是新一代驱动 |
| **MySQL** | `pymysql` | `aiomysql` | 纯 Python 实现 |
| **SQLite** | `sqlite3`（内置） | `aiosqlite` | 无需安装服务 |
| **MongoDB** | `pymongo` | `motor` | 非关系型数据库 |

**安装示例**

```bash
pip install psycopg2-binary        # PostgreSQL 同步
pip install asyncpg                # PostgreSQL 异步
pip install pymysql                # MySQL
```

### 1.2 直接使用驱动

**异步连接 PostgreSQL（asyncpg）**

```python
import asyncio
import asyncpg

async def main():
    # 建立连接池（生产环境用连接池复用连接）
    pool = await asyncpg.create_pool(
        user="postgres", password="secret",
        database="mydb", host="localhost", port=5432,
        min_size=5, max_size=20,
    )
    # 执行查询
    async with pool.acquire() as conn:
        rows = await conn.fetch("SELECT * FROM users WHERE age > $1", 18)
        print(rows)
    await pool.close()

asyncio.run(main())
```

**直接写 SQL 的缺点**：字符串拼接易出错、存在 SQL 注入风险、类型转换繁琐、难以维护 —— 这正是 ORM 要解决的问题。

## 二、SQLAlchemy 2.0 核心

### 2.1 概述与安装

**SQLAlchemy** 是 Python 最成熟的 ORM 库，2.0 版本引入了现代化的声明式 API。

```bash
pip install sqlalchemy
```

**SQLAlchemy 分层**

| 层 | 作用 |
|----|------|
| **Engine** | 数据库连接管理（连接池、方言） |
| **Connection** | 一次数据库连接 |
| **Session** | 业务单元，管理对象的增删改查（ORM 层） |
| **Declarative** | 用类定义表结构 |

### 2.2 Engine 与 Session

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, DeclarativeBase

# 1. 创建引擎（含连接池）
engine = create_engine(
    "postgresql+psycopg2://postgres:secret@localhost/mydb",
    echo=False,                    # True 时打印 SQL 日志
    pool_size=10,                  # 连接池大小
    max_overflow=20,               # 超出的最大连接数
)

# 2. 创建 Session 工厂
SessionLocal = sessionmaker(bind=engine, autocommit=False, autoflush=False)

# 3. 定义声明式基类
class Base(DeclarativeBase):
    pass

# 4. 使用 Session
with SessionLocal() as session:    # 上下文管理器自动关闭
    pass
```

### 2.3 定义模型（Declarative 映射）

```python
from sqlalchemy import String, Integer, DateTime, ForeignKey, Text, func
from sqlalchemy.orm import Mapped, mapped_column, relationship

class User(Base):
    __tablename__ = "users"                            # 表名

    id: Mapped[int] = mapped_column(primary_key=True)  # 主键
    name: Mapped[str] = mapped_column(String(50), unique=True)  # 唯一
    email: Mapped[str | None] = mapped_column(String(100))      # 可空
    age: Mapped[int] = mapped_column(Integer, default=0)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())

    posts: Mapped[list["Post"]] = relationship(back_populates="author")  # 关系

class Post(Base):
    __tablename__ = "posts"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    content: Mapped[str] = mapped_column(Text)
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id", ondelete="CASCADE"))

    author: Mapped[User] = relationship(back_populates="posts")  # 反向关系
```

**创建表（开发用）**

```python
# 生产环境用 Alembic 迁移，不用 create_all
Base.metadata.create_all(engine)
```

## 三、关系建模

### 3.1 三种关系

**一对多（ForeignKey）**

```python
class Post(Base):
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
```

| 关系类型 | 声明方式 | 场景 |
|---------|---------|------|
| **一对多** | 子表 `ForeignKey` + 父表 `relationship` | 用户 → 文章 |
| **多对多** | `association_table` + `relationship(secondary=...)` | 文章 → 标签 |
| **一对一** | `ForeignKey(unique=True)` + `uselist=False` | 用户 → 资料 |

**多对多**

```python
from sqlalchemy import Table, Column

# 关联表：存文章与标签的关系
post_tags = Table(
    "post_tags", Base.metadata,
    Column("post_id", ForeignKey("posts.id"), primary_key=True),
    Column("tag_id", ForeignKey("tags.id"), primary_key=True),
)

class Tag(Base):
    __tablename__ = "tags"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(30), unique=True)
    posts: Mapped[list[Post]] = relationship(secondary=post_tags, back_populates="tags")

# Post 中补充：
# tags: Mapped[list[Tag]] = relationship(secondary=post_tags, back_populates="posts")
```

### 3.2 级联行为

**ondelete** 控制数据库层的删除行为，`relationship` 的 `cascade` 控制 ORM 层。

```python
# 数据库层：删除用户时级联删除其文章
user_id: Mapped[int] = mapped_column(ForeignKey("users.id", ondelete="CASCADE"))

# ORM 层
class User(Base):
    posts: Mapped[list["Post"]] = relationship(
        back_populates="author",
        cascade="all, delete-orphan",   # 用户删除时级联删除文章
    )
```

## 四、查询 API

### 4.1 基础查询（select）

**SQLAlchemy 2.0** 使用函数式 `select`，替代旧版 `session.query`。

```python
from sqlalchemy import select, func
from sqlalchemy.orm import selectinload

# 查询所有
stmt = select(User)
users = session.execute(stmt).scalars().all()

# 条件过滤
stmt = select(User).where(User.age >= 18, User.name.like("张%"))
users = session.execute(stmt).scalars().all()

# 排序与分页
stmt = select(User).order_by(User.created_at.desc()).limit(10).offset(20)
users = session.execute(stmt).scalars().all()

# 取单条
user = session.execute(select(User).where(User.id == 1)).scalar_one_or_none()

# 聚合
count = session.execute(select(func.count(User.id))).scalar()

# 关联查询（join）
stmt = select(Post).join(User).where(User.name == "张三")
```

### 4.2 增删改（Session）

```python
# 新增
new_user = User(name="张三", age=20)
session.add(new_user)
session.commit()                    # 提交事务

# 修改
user = session.get(User, 1)         # 按主键取
user.age = 21
session.commit()

# 删除
session.delete(user)
session.commit()

# 批量新增
session.add_all([User(name=f"用户{i}") for i in range(10)])
session.commit()
```

**Session 使用原则**：一个请求一个 Session，用完即关；在 Web 框架中通常用依赖注入管理。

### 4.3 Lazy vs Eager Loading

**N+1 问题**：查询文章时默认只加载文章，访问 `post.author` 时才再查一次数据库，循环 100 篇文章就触发 100 次额外查询。

```python
# ❌ N+1：循环中逐个触发额外查询
for post in session.execute(select(Post)).scalars().all():
    print(post.author.name)   # 每篇文章都查一次 users 表 → 100 次查询

# ✅ Eager Loading：一次 JOIN 查出来
stmt = select(Post).options(selectinload(Post.author))
for post in session.execute(stmt).scalars().all():
    print(post.author.name)   # 只有 2 次查询
```

**加载策略**

| 策略 | 说明 |
|------|------|
| `selectinload` | 额外发一条 IN 查询批量加载（推荐） |
| `joinedload` | 用 LEFT JOIN 一次加载 |
| 默认（Lazy） | 访问时才查询（警惕 N+1） |

## 五、SQLModel 与 FastAPI

### 5.1 SQLModel 简介

**SQLModel** 是 FastAPI 作者开发的新一代 ORM，融合 Pydantic 与 SQLAlchemy，模型既可做数据校验又可做数据库表，与 FastAPI 无缝集成。

```bash
pip install sqlmodel
```

```python
from typing import Optional
from sqlmodel import SQLModel, Field, create_engine, Session, select

class Hero(SQLModel, table=True):            # table=True 表示数据库表
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(index=True)            # 加索引
    secret_name: str
    age: Optional[int] = None

# 建表（开发环境）
engine = create_engine("sqlite:///heroes.db")
SQLModel.metadata.create_all(engine)
```

### 5.2 与 FastAPI 集成

```python
from fastapi import FastAPI, Depends, HTTPException
from sqlmodel import SQLModel, Field, create_engine, Session, select

app = FastAPI()

# 数据库连接
engine = create_engine("sqlite:///app.db")
SQLModel.metadata.create_all(engine)

class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    secret_name: str
    age: int | None = None

# 每个请求一个 Session
def get_session():
    with Session(engine) as session:
        yield session

@app.post("/heroes", status_code=201)
def create_hero(hero: Hero, session: Session = Depends(get_session)):
    session.add(hero)
    session.commit()
    session.refresh(hero)        # 刷新获取数据库生成的主键
    return hero

@app.get("/heroes")
def list_heroes(session: Session = Depends(get_session)):
    return session.execute(select(Hero)).scalars().all()

@app.get("/heroes/{hero_id}")
def get_hero(hero_id: int, session: Session = Depends(get_session)):
    hero = session.get(Hero, hero_id)
    if not hero:
        raise HTTPException(status_code=404, detail="英雄不存在")
    return hero
```

**SQLModel vs 纯 SQLAlchemy**：SQLModel 代码更少、类型更安全、与 FastAPI 天然契合；SQLAlchemy 更成熟、控制力更强。

## 六、Alembic 迁移

### 6.1 初始化

**Alembic** 是 SQLAlchemy 的迁移工具，用于管理数据库结构的版本变更。

```bash
pip install alembic

# 初始化（生成 alembic/ 目录和 alembic.ini）
alembic init alembic
```

**配置 `alembic/env.py`**

```python
# env.py 关键部分：绑定模型元数据
import sys
from pathlib import Path
sys.path.append(str(Path(__file__).parent.parent))   # 项目根目录
from sqlalchemy import engine_from_config, pool
from alembic import context
from myapp.models import Base   # 导入你的 Base

target_metadata = Base.metadata
# 并同步修改 sqlalchemy.url = 你的数据库地址（或读取环境变量）
```

### 6.2 生成与执行迁移

```bash
# 1. 自动对比模型与数据库，生成迁移文件
alembic revision --autogenerate -m "add users table"

# 2. 应用到数据库
alembic upgrade head

# 3. 回滚一个版本
alembic downgrade -1
```

**迁移工作流**

| 步骤 | 命令 | 说明 |
|------|------|------|
| 修改模型 | 编辑 models.py | 添加/修改字段 |
| 生成迁移 | `alembic revision --autogenerate` | 生成迁移脚本 |
| 审查脚本 | 查看生成的 py 文件 | 确认自动生成无误 |
| 应用 | `alembic upgrade head` | 同步到数据库 |
| 团队协作 | 提交迁移文件 | 他人执行同一 upgrade |

## 七、异步数据库

### 7.1 SQLAlchemy 异步支持

**SQLAlchemy 2.0** 原生支持异步，配合 `asyncpg` 使用。

```python
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from sqlalchemy import text

# 异步引擎（连接串加 +asyncpg）
engine = create_async_engine("postgresql+asyncpg://postgres:secret@localhost/mydb")
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)

async def query():
    async with AsyncSessionLocal() as session:
        result = await session.execute(text("SELECT 1"))
        return result.scalar()
```

### 7.2 FastAPI 异步数据库

```python
# database.py
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker

engine = create_async_engine("sqlite+aiosqlite:///app.db")
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
```

```python
# main.py
from fastapi import FastAPI, Depends
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession
from database import get_db
from models import User

app = FastAPI()

@app.get("/users")
async def list_users(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(User))
    return result.scalars().all()
```

**同步 vs 异步数据库**：异步配合 FastAPI 的异步事件循环，同一连接可服务多个请求，高并发下吞吐更高；同步适合小规模应用，代码更简单。

**目标**：设计用户/文章/评论三张表，用 Alembic 管理迁移。

**步骤**：

1. 安装 `sqlalchemy`、`alembic`、`psycopg2-binary`
2. 定义 `User`、`Post`、`Comment` 模型（用户一对多文章，文章一对多评论）

5. 执行 `alembic upgrade head`，用数据库客户端确认表结构
6. 用 Session 编写增删改查，验证关系与级联
