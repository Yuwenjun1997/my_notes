# Docker 与部署

## 一、Docker 核心概念

### 1.1 什么是 Docker

Docker 是一个开源的**容器化平台**，将应用及其依赖打包成标准化的容器，实现"一次构建，处处运行"。

**镜像（Image） vs 容器（Container）**

| 概念 | 类比 | 说明 |
|------|------|------|
| **镜像** | 类的定义 | 只读模板，包含代码、运行时、依赖、配置 |
| **容器** | 类的实例 | 镜像的运行实例，可启动/停止/删除 |
| **仓库（Registry）** | Maven 中央仓库 | 存放和分发镜像（Docker Hub） |
| **卷（Volume）** | 持久化磁盘 | 容器内数据持久化到宿主机 |
| **网络（Network）** | 虚拟网卡 | 容器间通信与端口映射 |

**Docker vs 虚拟机对比**

| 对比维度 | Docker 容器 | 虚拟机 |
|---------|------------|--------|
| 虚拟化级别 | 进程级隔离 | 硬件级虚拟化 |
| 启动速度 | 秒级 | 分钟级 |
| 占用资源 | 小（共享内核） | 大（每个完整 OS） |
| 隔离性 | 较弱（共享内核） | 强（完全隔离） |
| 镜像大小 | MB 级 | GB 级 |

### 1.2 Docker 常用命令

```bash
# 镜像操作
docker pull python:3.12-slim     # 拉取镜像
docker images                    # 查看本地镜像
docker rmi python:3.12-slim      # 删除镜像

# 容器操作
docker run -d --name my-app -p 8000:8000 my-app:1.0    # 后台运行并映射端口
docker ps                        # 查看运行中容器
docker ps -a                     # 查看所有容器
docker logs -f my-app            # 实时查看容器日志
docker exec -it my-app bash      # 进入容器内部
docker stop my-app               # 停止容器
docker rm my-app                 # 删除容器

# 清理
docker system prune -a           # 清理所有未使用的镜像/容器/网络
```

### 1.3 Python 镜像选型

```bash
# 常见 Python 基础镜像
python:3.12                 # 完整版，包含编译工具（体积大 ~1GB）
python:3.12-slim            # 精简版，基于 Debian slim（~150MB）推荐
python:3.12-alpine          # 极简版，基于 Alpine Linux（~50MB，可能有兼容问题）
```

**镜像选型建议**

| 镜像 | 体积 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| `python:3.12` | ~1GB | 环境完整，编译无障碍 | 体积大，构建慢 | 需要编译依赖的开发环境 |
| `python:3.12-slim` | ~150MB | 体积适中，Debian 兼容好 | 缺少部分编译工具 | **生产首选** |
| `python:3.12-alpine` | ~50MB | 体积最小 | musl libc 可能不兼容某些轮子 | 依赖简单的场景 |

## 二、Dockerfile 最佳实践

### 2.1 基础 Dockerfile

```dockerfile
# Dockerfile — FastAPI 应用镜像
# 1. 使用精简版 Python 镜像
FROM python:3.12-slim

# 2. 设置工作目录与环境变量
WORKDIR /app
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

# 3. 先复制依赖文件再安装，利用 Docker 层缓存
COPY requirements.txt .
RUN pip install -r requirements.txt

# 4. 复制业务代码
COPY . .

# 5. 声明端口与非 root 用户
EXPOSE 8000
USER nobody

# 6. 启动命令（生产用 gunicorn，见下文）
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**层缓存优化**

```
❌ 先复制全部代码再装依赖：
COPY . .
RUN pip install -r requirements.txt
# 每次改一行代码，pip install 都要重新执行

✅ 先复制依赖文件，再复制代码：
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
# 只要 requirements.txt 不变，pip 层可复用缓存，构建速度快很多
```

### 2.2 多阶段构建

```dockerfile
# 阶段一：构建依赖（含编译工具）
FROM python:3.12-slim AS builder

WORKDIR /app
COPY requirements.txt .

# 创建仅包含运行期依赖的目录
RUN pip install --user --prefix=/install -r requirements.txt

# 阶段二：运行时（不包含编译工具，镜像更小）
FROM python:3.12-slim

WORKDIR /app
COPY --from=builder /install /usr/local
COPY . .

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**使用 uv 加速依赖安装**

```dockerfile
FROM python:3.12-slim AS builder

# 安装 uv（超快的 Python 包管理器）
COPY --from=ghcr.io/astral-sh/uv:latest /uv /bin/uv
COPY requirements.txt .

# 利用 uv 缓存，编译并锁定依赖
RUN uv pip install --system --compile-bytecode -r requirements.txt

FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.12/site-packages /usr/local/lib/python3.12/site-packages
COPY . .
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### 2.3 构建与运行

```bash
# 构建镜像（-t 打标签）
docker build -t fastapi-app:1.0 .

# 运行容器（-p 宿主机端口:容器端口，-v 挂载卷）
docker run -d \
  --name fastapi-app \
  -p 8000:8000 \
  -e DATABASE_URL="mysql://user:pass@host/db" \
  --restart unless-stopped \
  fastapi-app:1.0

# 推送到 Docker Hub
docker tag fastapi-app:1.0 myname/fastapi-app:1.0
docker push myname/fastapi-app:1.0
```

## 三、docker-compose 编排

### 3.1 Compose 基础

docker-compose 用 YAML 文件定义并管理**多个容器**，一键启动整个应用栈。

```yaml
# docker-compose.yml — FastAPI + Redis + MySQL 组合
version: "3.8"

services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=mysql+pymysql://app:secret@db:3306/app_db
      - REDIS_URL=redis://redis:6379/0
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  db:
    image: mysql:8.0
    environment:
      - MYSQL_ROOT_PASSWORD=root
      - MYSQL_DATABASE=app_db
      - MYSQL_USER=app
      - MYSQL_PASSWORD=secret
    volumes:
      - db_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  redis_data:
  db_data:
```

**Compose 常用命令**

```bash
docker compose up -d             # 后台启动全部服务
docker compose up -d --build     # 重新构建并启动
docker compose ps                # 查看服务状态
docker compose logs -f api       # 查看某服务日志
docker compose down              # 停止并删除容器/网络
docker compose down -v           # 连同数据卷一起删除
docker compose exec api bash     # 进入某服务容器
```

### 3.2 健康检查与依赖启动顺序

```bash
# 容器启动顺序问题：
# depends_on 只控制启动顺序，不保证"就绪"
# 解决方案：healthcheck 条件等待（见上方 compose 配置）

# 排查容器是否就绪
docker inspect --format='{{json .State.Health}}' fastapi-app
# 输出 {"Status":"healthy","FailingStreak":0,...}
```

## 四、生产部署

### 4.1 生产服务器选择

FastAPI 开发时用 `uvicorn` 单进程，生产环境需要多进程 + 自动重启。

**Uvicorn**

```bash
# 单进程（仅开发用）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 多 worker（利用多核 CPU）
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
```

**Gunicorn + Uvicorn Worker**

```bash
# 推荐：gunicorn 作为进程管理器，uvicorn worker 处理请求
gunicorn app.main:app \
  -w 4 \                                    # 4 个 worker 进程
  -k uvicorn.workers.UvicornWorker \        # 使用 Uvicorn worker
  --bind 0.0.0.0:8000 \
  --timeout 60 \
  --max-requests 1000 \                     # 每个 worker 处理 1000 请求后重启（防内存泄漏）
  --max-requests-jitter 100 \
  --access-logfile - \
  --error-logfile -
```

**多进程部署注意事项**

1. **worker 数量**：`CPU 核心数 × 2 + 1` 经验值
2. **共享状态**：多进程无法共享内存，分布式锁/缓存用 Redis
3. **启动钩子**：`--preload` 提前加载应用，避免每个 worker 重复导入

**Gunicorn vs Uvicorn 对比**

| 对比维度 | Gunicorn | Uvicorn |
|---------|----------|---------|
| 定位 | WSGI 进程管理器 | ASGI 服务器 |
| 异步支持 | 通过 worker 类型支持 | 原生异步 |
| 进程管理 | 成熟（重载/优雅退出） | 较弱 |
| 生产推荐 | 前端 gunicorn 管进程 | 后端 uvicorn 跑请求 |

### 4.2 环境变量与配置管理

```python
# config.py — 使用 pydantic-settings 管理配置
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    app_name: str = "FastAPI App"
    database_url: str = "sqlite:///./app.db"
    redis_url: str = "redis://localhost:6379/0"
    debug: bool = False

    # 从 .env 文件加载
    model_config = {"env_file": ".env", "env_file_encoding": "utf-8"}


settings = Settings()
```

```bash
# .env 文件（不入 git，生产用环境变量注入）
DATABASE_URL=mysql+pymysql://app:secret@db:3306/app_db
REDIS_URL=redis://redis:6379/0
DEBUG=false
```

```yaml
# docker-compose 中注入环境变量
services:
  api:
    env_file:
      - .env
    # 或直接覆盖
    environment:
      - DEBUG=false
```

### 4.3 Nginx 反向代理 + HTTPS

**Nginx 配置**

```nginx
# nginx.conf
server {
    listen 80;
    server_name api.example.com;

    # 反向代理到 FastAPI
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # WebSocket 支持
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        # 长请求超时
        proxy_read_timeout 60s;
    }

    # 静态资源（由 Nginx 直接响应）
    location /static/ {
        alias /var/www/app/static/;
        expires 7d;
    }

    # 大文件上传
    client_max_body_size 50m;
}
```

**配置 HTTPS（certbot）**

```bash
# 安装并申请免费证书
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d api.example.com

# 自动续期（默认写入 cron）
sudo certbot renew --dry-run

# 手动续期测试
certbot renew --force-renewal
```

**systemd 托管应用**

```ini
# /etc/systemd/system/fastapi.service
[Unit]
Description=FastAPI Application
After=network.target

[Service]
User=www-data
WorkingDirectory=/srv/app
EnvironmentFile=/srv/app/.env
ExecStart=/srv/app/.venv/bin/gunicorn app.main:app \
    -w 4 -k uvicorn.workers.UvicornWorker \
    --bind 127.0.0.1:8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fastapi
sudo systemctl status fastapi
sudo journalctl -u fastapi -f        # 实时查看日志
```

**目标**：将已有的 FastAPI 待办 API 容器化，用 docker-compose 一键启动 API + Redis + MySQL。

**步骤**：
