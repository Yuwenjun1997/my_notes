# Netty 与 NIO 网络编程

> 本文档全面覆盖 Java NIO 与 Netty 框架的核心知识体系，从 IO 模型演进到高级特性实战，适用于初中级 Java 工程师进阶学习。

---

## 1. IO 模型演进

### 1.1 阻塞 IO (BIO) — 每个连接一个线程

**BIO (Blocking IO)** 是最传统的网络编程模型。在 `accept()`、`read()`、`write()` 等系统调用上，线程会**阻塞**直到操作完成。

```
┌─────────┐  accept()  ┌──────────┐  read()   ┌──────────┐
│ Main    │ ────────→  │ Thread-1 │ ────────→  │ 阻塞等待  │
│ Thread  │            │ (连接1)   │            │ 客户端数据 │
│         │  accept()  ┌──────────┐            └──────────┘
│         │ ────────→  │ Thread-2 │
│         │            │ (连接2)   │
└─────────┘            └──────────┘
```

#### 原理

- 服务端每接受一个连接（`accept()`），就创建一个新线程处理该连接的所有 IO 操作。
- 线程在数据就绪前**完全阻塞**，CPU 资源被浪费在线程上下文切换上。
- **C10K 问题**：当连接数达到上万级别，线程数过多导致系统不堪重负。

#### 代码示例

```java
import java.io.*;
import java.net.*;

public class BioEchoServer {
    public static void main(String[] args) throws IOException {
        ServerSocket serverSocket = new ServerSocket(8080);
        System.out.println("BIO Echo Server 启动，端口: 8080");

        while (true) {
            // accept() 阻塞，直到新连接到达
            Socket clientSocket = serverSocket.accept();
            System.out.println("新连接: " + clientSocket.getRemoteSocketAddress());

            // 每个连接创建一个新线程
            new Thread(() -> {
                try (BufferedReader in = new BufferedReader(
                        new InputStreamReader(clientSocket.getInputStream()));
                     PrintWriter out = new PrintWriter(
                             clientSocket.getOutputStream(), true)) {

                    String line;
                    // readLine() 阻塞，直到读到换行符或流关闭
                    while ((line = in.readLine()) != null) {
                        System.out.println("收到: " + line);
                        out.println("Echo: " + line);
                    }
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }).start();
        }
    }
}
```

**缺点**：
- 线程数 = 连接数，资源消耗极大
- 大量线程在等待 IO 时阻塞，CPU 利用率低
- 可以用线程池改善，但线程池大小有限，无法支撑海量连接

### 1.2 非阻塞 IO (NIO) — 单线程轮询多路复用器

**NIO (Non-blocking IO / New IO)** 引入 **Selector（多路复用器）**，一个线程可以同时管理成千上万个通道。

```
┌────────────┐  select()   ┌──────────────┐
│ 单线程     │ ──────────→  │ 就绪事件集合   │
│ (Selector  │             │ ┌──────────┐ │
│  轮询)     │             │ │ Channel1  │ │ → read()
│            │             │ │ Channel2  │ │ → write()
│            │             │ │ Channel3  │ │ → accept()
│            │             │ │ ......    │ │
└────────────┘             │ └──────────┘ │
                           └──────────────┘
```

#### 核心思想

- 将通道（Channel）注册到 Selector 上，并指明感兴趣的事件（OP_ACCEPT、OP_READ、OP_WRITE）。
- 单线程调用 `selector.select()` 阻塞（或超时），当有通道就绪时才返回，遍历 `selectedKeys` 处理。
- **一个线程处理所有连接**，避免了线程上下文切换的开销。

#### 代码对比：非阻塞模式

```java
// 设置 Channel 为非阻塞模式
SocketChannel channel = SocketChannel.open();
channel.configureBlocking(false); // 关键：非阻塞
channel.connect(new InetSocketAddress("localhost", 8080));

while (!channel.finishConnect()) {
    // 连接未完成时可以做其他事，不会阻塞
    System.out.println("等待连接中，先干点别的...");
}
```

### 1.3 IO 多路复用：select / poll / epoll 原理对比

操作系统层面提供了三种多路复用机制，性能和适用场景差异巨大。

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| 平台 | 所有类 Unix | 所有类 Unix | Linux 2.6+ |
| 最大连接数 | 1024 (FD_SETSIZE) | 无上限（链表） | 无上限（事件表） |
| 数据结构 | bitmap | 链表 | 红黑树 + 就绪链表 |
| 遍历方式 | 线性扫描全部 fd | 线性扫描全部 fd | 仅遍历就绪 fd（回调） |
| 触发模式 | LT（水平触发） | LT（水平触发） | LT / ET（边缘触发） |
| 用户态→内核态 | 每次传入全部 fd | 每次传入全部 fd | 通过 mmap 共享内存 |
| 性能瓶颈 | O(n) 随 fd 增多线性下降 | O(n) 同 select | O(1) 仅处理活跃连接 |
| Java 支持 | ❌ 不直接支持 | ❌ 不直接支持 | ✅ Linux 下 NIO 默认使用 |

#### epoll 核心机制

```
应用层                         内核
 ├─ epoll_create()  ──────────→ 创建 epoll 实例（红黑树 + 就绪链表）
 ├─ epoll_ctl(ADD)   ──────────→ 将 fd 加入红黑树，注册回调
 ├─ epoll_wait()     ──────────→ 等待就绪链表非空（可设置超时）
 │                              当 fd 就绪时，回调将 fd 加入就绪链表
 │                              返回就绪链表中的 fd 集合
 └─ 处理就绪事件
```

**边缘触发 (ET) vs 水平触发 (LT)**：

```java
// LT（水平触发）：只要缓冲区有数据，每次 select 都会通知
//    → 编程简单，但可能重复通知
// ET（边缘触发）：仅数据到达的瞬间通知一次
//    → 效率高，但必须一次读完所有数据，否则永远丢失
// Java NIO 默认使用 LT 模式
```

### 1.4 异步 IO (AIO) — Proactor 模式

**AIO (Asynchronous IO)** 是 Java 7 引入的，真正由操作系统完成的异步 IO —— 提交 IO 请求后立即返回，操作完成后由内核通知用户代码（回调或 Future）。

```
┌─────────┐  read()  ┌──────────┐ 数据就绪  ┌──────────┐
│ 用户线程  │ ────────→│  内核     │ ────────→│ 回调/通知  │
│ (非阻塞)  │          │           │          │ CompletionHandler │
└─────────┘          └──────────┘          └──────────┘
      ↓                                    ↑
   立即返回                              自动调用回调
```

#### 代码示例

```java
import java.nio.channels.*;
import java.nio.ByteBuffer;
import java.net.InetSocketAddress;

public class AioEchoServer {
    public static void main(String[] args) throws Exception {
        AsynchronousServerSocketChannel server =
                AsynchronousServerSocketChannel.open().bind(new InetSocketAddress(8080));

        System.out.println("AIO Echo Server 启动，端口: 8080");

        server.accept(null, new CompletionHandler<AsynchronousSocketChannel, Void>() {
            @Override
            public void completed(AsynchronousSocketChannel ch, Void attachment) {
                // 立即继续接受下一个连接（否则只能处理一个）
                server.accept(null, this);
                handleClient(ch);
            }

            @Override
            public void failed(Throwable exc, Void attachment) {
                System.err.println("接受连接失败: " + exc.getMessage());
            }
        });

        // 主线程不能退出
        Thread.currentThread().join();
    }

    private static void handleClient(AsynchronousSocketChannel ch) {
        ByteBuffer buf = ByteBuffer.allocate(1024);
        ch.read(buf, null, new CompletionHandler<Integer, Void>() {
            @Override
            public void completed(Integer bytesRead, Void attachment) {
                if (bytesRead > 0) {
                    buf.flip();
                    // echo 回去
                    ch.write(buf);
                    buf.clear();
                    // 继续读
                    ch.read(buf, null, this);
                }
            }

            @Override
            public void failed(Throwable exc, Void attachment) {
                System.err.println("读取失败: " + exc.getMessage());
            }
        });
    }
}
```

> **现实情况**：AIO 在 Windows 上通过 IOCP 实现性能尚可，但在 Linux 上底层仍用 epoll 模拟异步，性能不如 Netty 优化后的 NIO。因此 **Netty 在 Linux 上弃用 AIO，仍然使用 NIO 多路复用**。**实际项目中基本不用 AIO，Netty 是主流方案。**

### 1.5 五大 IO 模型对比表格

| IO 模型 | 阻塞点 | 线程模型 | 并发能力 | 复杂度 | 适用场景 |
|---------|--------|----------|---------|--------|---------|
| **阻塞 BIO** | accept/read/write | 一线程一连接 | 差（C10K） | 低 | 连接数少、传统项目 |
| **非阻塞 NIO** | 无（轮询） | 单线程处理多连接 | 较高 | 中 | 较少使用（需自研协议） |
| **IO 多路复用** | select/epoll | 单线程轮询事件 | 高（C1000K） | 中 | Netty、Redis、Nginx |
| **信号驱动** | 无 | 回调驱动 | 较高 | 高 | 不常用 |
| **异步 AIO** | 无（内核完成） | 回调/Proactor | 较高 | 高 | Windows IOCP 可用 |
| **Netty** | 无 | Reactor 模型 | 极高 | 封装良好 | **工业首选** |

## 2. Java NIO 核心

NIO 的三大核心组件：**Channel（通道）**、**Buffer（缓冲区）**、**Selector（选择器）**。

### 2.1 Channel（通道）

Channel 是双向的，既可以读也可以写，而传统的 Stream 是单向的。

| Channel 类型 | 说明 |
|-------------|------|
| `FileChannel` | 文件 IO，**非阻塞模式不适用于文件**（文件 IO 无多路复用） |
| `SocketChannel` | TCP 客户端通道 |
| `ServerSocketChannel` | TCP 服务端通道 |
| `DatagramChannel` | UDP 通道 |

```java
// FileChannel 示例
FileChannel fileChannel = FileChannel.open(
        Path.of("test.txt"), StandardOpenOption.READ);
ByteBuffer buf = ByteBuffer.allocate(1024);
int bytesRead = fileChannel.read(buf); // 文件没有非阻塞模式

// SocketChannel 示例
SocketChannel socketChannel = SocketChannel.open();
socketChannel.configureBlocking(false); // 设为非阻塞
socketChannel.connect(new InetSocketAddress("localhost", 8080));
// 非阻塞 connect 需要 finishConnect() 完成连接
while (!socketChannel.finishConnect()) {
    // 等待连接完成
}

// ServerSocketChannel
ServerSocketChannel serverChannel = ServerSocketChannel.open();
serverChannel.configureBlocking(false);
serverChannel.bind(new InetSocketAddress(8080));
// 非阻塞 accept：没有连接时返回 null
SocketChannel client = serverChannel.accept();
if (client != null) {
    // 处理新连接
}
```

### 2.2 Buffer（缓冲区）

Buffer 本质上是一块**内存区域**，用于 Channel 读写数据。核心属性：

```
position  →  当前读写位置
limit     →  可读/可写的界限
capacity  →  缓冲区总容量

初始状态（写模式）：
┌──────┬──────┬──────┬──────┬──────┐
│      │      │      │      │      │
│ free │ free │ free │ free │ free │
│      │      │      │      │      │
└──────┴──────┴──────┴──────┴──────┘
↑                              ↑     ↑
position=0                    limit=capacity=5

写入 3 个字节后：
┌──────┬──────┬──────┬──────┬──────┐
│ data │ data │ data │      │      │
│  1   │  2   │  3   │ free │ free │
└──────┴──────┴──────┴──────┴──────┘
↑                    ↑            ↑
position=3          limit=5     capacity=5

flip() 后（读模式）：
┌──────┬──────┬──────┬──────┬──────┐
│ data │ data │ data │      │      │
│  1   │  2   │  3   │ free │ free │
└──────┴──────┴──────┴──────┴──────┘
↑                    ↑            ↑
position=0          limit=3     capacity=5

clear() 后（重置为写模式）：
┌──────┬──────┬──────┬──────┬──────┐
│      │      │      │      │      │
│ free │ free │ free │ free │ free │
└──────┴──────┴──────┴──────┴──────┘
↑                              ↑     ↑
position=0                    limit=capacity=5
```

#### 关键方法

```java
public class ByteBufferExample {
    public static void main(String[] args) {
        // 分配堆内存缓冲区
        ByteBuffer buf = ByteBuffer.allocate(10);

        // 写入数据
        buf.put((byte) 'H');
        buf.put((byte) 'e');
        buf.put((byte) 'l');
        buf.put((byte) 'l');
        buf.put((byte) 'o');

        System.out.printf("写入后 → position=%d, limit=%d, capacity=%d%n",
                buf.position(), buf.limit(), buf.capacity());
        // position=5, limit=10, capacity=10

        // flip：切换为读模式
        buf.flip();
        System.out.printf("flip后 → position=%d, limit=%d%n",
                buf.position(), buf.limit());
        // position=0, limit=5

        // 读取数据
        while (buf.hasRemaining()) {
            System.out.print((char) buf.get());
        }
        System.out.println();
        // 输出: Hello

        // clear：重置为写模式（但数据还在，position/limit 重置）
        buf.clear();
        System.out.printf("clear后 → position=%d, limit=%d%n",
                buf.position(), buf.limit());
        // position=0, limit=10

        // compact：将未读数据移到头部
        buf.put((byte) 'A').put((byte) 'B').put((byte) 'C');
        buf.flip();
        buf.get(); // 读走 'A'
        buf.compact(); // 'B' 'C' 被移到头部
        System.out.printf("compact后 → position=%d (已移动2字节)%n", buf.position());
        // position=2 (BC 被保留在 0-1 位置)

        // 直接内存缓冲区（零拷贝）
        ByteBuffer directBuf = ByteBuffer.allocateDirect(1024);
        System.out.println("直接内存: " + directBuf.isDirect());
        // 直接缓冲区在堆外，避免 GC 和内核-用户态拷贝，适合 IO 密集型场景
    }
}
```

#### 应用：从 Channel 写入 Buffer 的典型模式

```java
// 循环读取，直到 EOF
ByteBuffer buf = ByteBuffer.allocate(1024);
int bytesRead;
while ((bytesRead = channel.read(buf)) != -1) {
    buf.flip();     // 切换为读模式
    while (buf.hasRemaining()) {
        byte b = buf.get();
        // 处理每个字节
    }
    buf.clear();    // 或 buf.compact()，切换回写模式
}
```

### 2.3 Selector（选择器）

Selector 是 NIO 多路复用的核心，通过 `select()` 方法监听已注册 Channel 上的 IO 事件。

#### 核心流程

```java
// 1. 创建 Selector
Selector selector = Selector.open();

// 2. 创建 ServerSocketChannel 并设为非阻塞
ServerSocketChannel serverChannel = ServerSocketChannel.open();
serverChannel.configureBlocking(false);
serverChannel.bind(new InetSocketAddress(8080));

// 3. 注册 ACCEPT 事件到 Selector
SelectionKey key = serverChannel.register(selector, SelectionKey.OP_ACCEPT);

// 4. 事件循环
while (true) {
    // 阻塞，直到有事件就绪（或超时）
    int readyCount = selector.select(1000); // 超时 1 秒
    if (readyCount == 0) continue;

    // 5. 获取就绪事件集合
    Set<SelectionKey> selectedKeys = selector.selectedKeys();
    Iterator<SelectionKey> iter = selectedKeys.iterator();

    while (iter.hasNext()) {
        SelectionKey sk = iter.next();
        iter.remove(); // 必须手动移除，否则下次仍会返回

        if (sk.isAcceptable()) {
            // ACCEPT 事件
            ServerSocketChannel ssc = (ServerSocketChannel) sk.channel();
            SocketChannel client = ssc.accept();
            client.configureBlocking(false);
            client.register(selector, SelectionKey.OP_READ);
            System.out.println("新连接: " + client.getRemoteAddress());
        }

        if (sk.isReadable()) {
            // READ 事件
            SocketChannel client = (SocketChannel) sk.channel();
            ByteBuffer buf = ByteBuffer.allocate(1024);
            int bytesRead = client.read(buf);
            if (bytesRead == -1) {
                client.close(); // 客户端关闭
            } else {
                buf.flip();
                // 处理读取的数据...
            }
        }
    }
}
```

#### SelectionKey 操作

```java
// 注册时返回的 key 可附加自定义对象
SelectionKey key = channel.register(selector, SelectionKey.OP_READ, attachmentObj);

// 常用方法
key.interestOps(SelectionKey.OP_WRITE);     // 修改感兴趣的事件
key.interestOps(key.interestOps() | SelectionKey.OP_WRITE); // 增加事件
key.interestOps(key.interestOps() & ~SelectionKey.OP_READ); // 移除事件
key.attach(obj);                            // 附加对象
Object obj = key.attachment();              // 获取附加对象
key.cancel();                               // 取消注册
```

### 2.4 用 NIO 实现一个完整的 Echo 服务器

```java
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.ByteBuffer;
import java.nio.channels.*;
import java.util.Iterator;
import java.util.Set;

/**
 * 基于 Java NIO 实现的 Echo 服务器
 * 单线程处理所有连接，演示 NIO 多路复用核心机制
 */
public class NioEchoServer {
    public static void main(String[] args) throws IOException {
        Selector selector = Selector.open();

        ServerSocketChannel serverChannel = ServerSocketChannel.open();
        serverChannel.configureBlocking(false);
        serverChannel.bind(new InetSocketAddress(8080));
        serverChannel.register(selector, SelectionKey.OP_ACCEPT);

        System.out.println("NIO Echo Server 启动，端口: 8080");

        while (true) {
            // 阻塞等待事件就绪
            selector.select();
            Set<SelectionKey> selectedKeys = selector.selectedKeys();
            Iterator<SelectionKey> iter = selectedKeys.iterator();

            while (iter.hasNext()) {
                SelectionKey key = iter.next();
                iter.remove();

                try {
                    if (key.isAcceptable()) {
                        handleAccept(key, selector);
                    } else if (key.isReadable()) {
                        handleRead(key, selector);
                    }
                } catch (IOException e) {
                    // 异常关闭连接
                    key.channel().close();
                    System.err.println("连接异常: " + e.getMessage());
                }
            }
        }
    }

    private static void handleAccept(SelectionKey key, Selector selector) throws IOException {
        ServerSocketChannel ssc = (ServerSocketChannel) key.channel();
        SocketChannel client = ssc.accept();
        client.configureBlocking(false);

        // 将客户端通道注册到 Selector，关注 READ 事件
        // 同时附加一个 ByteBuffer 用于读写数据
        client.register(selector, SelectionKey.OP_READ,
                ByteBuffer.allocate(1024));
        System.out.println("新连接: " + client.getRemoteAddress());
    }

    private static void handleRead(SelectionKey key, Selector selector) throws IOException {
        SocketChannel client = (SocketChannel) key.channel();
        ByteBuffer buf = (ByteBuffer) key.attachment();
        buf.clear();

        int bytesRead = client.read(buf);
        if (bytesRead == -1) {
            // 客户端关闭连接
            System.out.println("客户端断开: " + client.getRemoteAddress());
            client.close();
            return;
        }

        buf.flip();
        // 读取数据
        byte[] data = new byte[buf.limit()];
        buf.get(data);
        String msg = new String(data);
        System.out.println("收到: " + msg);

        // Echo 回客户端
        buf.rewind();  // position 重置为 0
        client.write(buf);
    }
}
```

## 3. Netty 核心架构

Netty 在 NIO 之上封装了**Reactor 线程模型**，极大简化了网络编程复杂度。

### 3.1 Reactor 线程模型

Reactor 模式包含两个核心角色：
- **Reactor**：负责监听和分发事件（相当于 Selector + 调度）
- **Handler**：负责处理具体业务逻辑（相当于 ChannelHandler）

#### 单线程 Reactor 模型

```
┌─────────────────────────────────────┐
│            Reactor 单线程             │
│  ┌────────────┐   ┌──────────────┐  │
│  │  Selector  │ → │  Handler     │  │
│  │  (accept)  │   │  (业务处理)   │  │
│  │  (read)    │   │  (编解码)     │  │
│  │  (write)   │   │  (业务逻辑)   │  │
│  └────────────┘   └──────────────┘  │
└─────────────────────────────────────┘

问题：一个线程既做 IO 又做业务，如果业务慢会阻塞所有连接。
适用：仅适用于 Handler 极快的场景（如 Redis 单线程模型）。
```

#### 多线程 Reactor 模型

```
┌──────────────────────┐
│  Reactor 线程 (boss)  │
│  ┌────────────────┐  │
│  │ Selector       │  │ ← accept 事件
│  │ (OP_ACCEPT)    │  │
│  └───────┬────────┘  │
└──────────┼───────────┘
           │ 将 SocketChannel 分发给 Worker 线程
           ▼
┌───────────────────────────────────┐
│       Worker 线程池                 │
│  ┌──────────────┐                 │
│  │ Selector     │ ← read/write    │
│  │ + Handler    │                  │
│  ├──────────────┤                 │
│  │ Selector     │                  │
│  │ + Handler    │                  │
│  └──────────────┘                 │
└───────────────────────────────────┘

优势：IO 事件处理与业务处理分离，避免单线程瓶颈。
```

#### 主从多线程 Reactor 模型（Netty 默认）

```
┌─────────────────────────────────┐
│      Boss EventLoopGroup        │
│  ┌────────────┐ ┌────────────┐  │
│  │ EventLoop1 │ │ EventLoop2 │  │  ← 处理 accept
│  │ (Selector) │ │ (Selector) │  │
│  └──────┬─────┘ └──────┬─────┘  │
└─────────┼──────────────┼────────┘
          │              │
          ▼              ▼
┌──────────────────────────────────┐
│     Worker EventLoopGroup        │
│  ┌────────────┐ ┌────────────┐   │
│  │ EventLoop1 │ │ EventLoop2 │   │  ← 处理 read/write
│  │ (Selector) │ │ (Selector) │   │
│  ├────────────┤ ├────────────┤   │
│  │ EventLoop3 │ │ EventLoop4 │   │
│  └────────────┘ └────────────┘   │
└──────────────────────────────────┘

特点：
- Boss Group：只负责 accept 连接，通常 1 个线程就够
- Worker Group：负责读写 IO 和业务处理，线程数通常 = CPU 核心数 × 2
- 每个 EventLoop 绑定一个 Selector 和一个线程
```

### 3.2 Netty 的 EventLoopGroup 和 EventLoop

```java
// 典型 Netty 服务端启动代码
public class NettyServer {
    public static void main(String[] args) {
        // Boss Group: 处理 accept 事件，线程数建议 1（默认 = CPU 核心数 × 2）
        EventLoopGroup bossGroup = new NioEventLoopGroup(1);

        // Worker Group: 处理 read/write 事件，默认线程数 = CPU 核心数 × 2
        EventLoopGroup workerGroup = new NioEventLoopGroup();

        try {
            ServerBootstrap b = new ServerBootstrap();
            b.group(bossGroup, workerGroup)
             .channel(NioServerSocketChannel.class)
             .childHandler(new ChannelInitializer<SocketChannel>() {
                 @Override
                 protected void initChannel(SocketChannel ch) {
                     ch.pipeline().addLast(new EchoServerHandler());
                 }
             })
             .bind(8080).sync()
             .channel().closeFuture().sync();
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        } finally {
            bossGroup.shutdownGracefully();
            workerGroup.shutdownGracefully();
        }
    }
}
```

#### EventLoop 内部结构

```
EventLoop (extends SingleThreadEventLoop)
├── Thread (绑定的唯一线程，不可更换)
├── Selector (NIO 多路复用器)
├── TaskQueue (普通任务队列)
├── ScheduledTaskQueue (定时任务队列)
└── Channel 集合 (注册到此 EventLoop 的所有 Channel)

执行流程：
1. 调用 Selector.select(timeout) 等待 IO 事件
2. 处理 IO 事件（selectedKeys）
3. 执行 TaskQueue 中的普通任务
4. 执行 ScheduledTaskQueue 中的定时任务
5. 回到步骤 1（循环）
```

### 3.3 Channel 和 ChannelPipeline

#### Netty 的 Channel 继承体系

```
Channel (接口)
├── NioServerSocketChannel  — 服务端监听通道（Boss 使用）
├── NioSocketChannel        — 客户端/服务端通信通道（Worker 使用）
├── OioSocketChannel        — BIO 模式（已弃用）
├── EpollSocketChannel      — Linux epoll 原生通道（性能更优）
└── KQueueSocketChannel     — macOS kqueue 原生通道
```

#### ChannelPipeline

```
一个 Channel 对应一个 ChannelPipeline（双向链表）

                    入站方向 (Inbound) →
                    
  ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
  │ Handler │ → │ Handler │ → │ Handler │ → │ Handler │
  │  A      │   │  B      │   │  C      │   │  D      │
  │ (Inbound)│   │ (In/Out)│   │ (Outbound)│   │ (Outbound)│
  └─────────┘   └─────────┘   └─────────┘   └─────────┘
                          ← 出站方向 (Outbound)
                          
  HeadContext ← ... ← TailContext (Netty 自动添加)
```

#### 代码验证执行顺序

```java
public class PipelineOrderHandler1 extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        System.out.println("Inbound Handler 1");       // 第一个输出

    }
}

public class PipelineOrderHandler2 extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        System.out.println("Inbound Handler 2");       // 第二个输出
        ctx.fireChannelRead(msg);
    }
}

public class OutboundHandler1 extends ChannelOutboundHandlerAdapter {
    @Override
    public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
        System.out.println("Outbound Handler 1");      // 第四个输出（出站反向）
        ctx.write(msg, promise);
    }
}

public class OutboundHandler2 extends ChannelOutboundHandlerAdapter {
    @Override
    public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
        System.out.println("Outbound Handler 2");      // 第三个输出（更靠近尾部）

    }
}

// 添加顺序
pipeline.addLast("in1", new PipelineOrderHandler1());   // 位置 1
pipeline.addLast("in2", new PipelineOrderHandler2());   // 位置 2
pipeline.addLast("out2", new OutboundHandler2());       // 位置 3
pipeline.addLast("out1", new OutboundHandler1());       // 位置 4

// 执行顺序：
// 入站事件（如 channelRead）：in1 → in2 (正向)
// 出站事件（如 write）：out1 → out2 (反向，从尾部往前)
```

### 3.4 Bootstrap 和 ServerBootstrap

| 特性 | Bootstrap | ServerBootstrap |
|------|-----------|-----------------|
| 角色 | 客户端 | 服务端 |
| 功能 | 连接远程服务 | 绑定本地端口监听 |
| 线程组 | 1 个 EventLoopGroup | 2 个 EventLoopGroup（boss + worker） |
| Channel 类型 | NioSocketChannel | NioServerSocketChannel |
| Handler 配置 | `handler()` | `handler()`（boss）+ `childHandler()`（worker） |

```java
// ========== 客户端 Bootstrap ==========
EventLoopGroup group = new NioEventLoopGroup();
try {
    Bootstrap b = new Bootstrap();
    b.group(group)
     .channel(NioSocketChannel.class)
     .option(ChannelOption.TCP_NODELAY, true)  // 客户端参数
     .handler(new ChannelInitializer<SocketChannel>() {
         @Override
         protected void initChannel(SocketChannel ch) {
             ch.pipeline().addLast(new StringDecoder());
             ch.pipeline().addLast(new StringEncoder());
             ch.pipeline().addLast(new ClientHandler());
         }
     });

    // 连接服务器
    ChannelFuture future = b.connect("localhost", 8080).sync();
    future.channel().closeFuture().sync();
} finally {
    group.shutdownGracefully();
}

// ========== 服务端 ServerBootstrap ==========
EventLoopGroup boss = new NioEventLoopGroup(1);
EventLoopGroup worker = new NioEventLoopGroup();
try {
    ServerBootstrap b = new ServerBootstrap();
    b.group(boss, worker)
     .channel(NioServerSocketChannel.class)
     .option(ChannelOption.SO_BACKLOG, 128)    // 服务端 accept 队列大小
     .option(ChannelOption.SO_REUSEADDR, true)  // 端口重用
     .childOption(ChannelOption.TCP_NODELAY, true) // 子通道参数
     .childOption(ChannelOption.SO_KEEPALIVE, true)
     .handler(new LoggingHandler(LogLevel.INFO))       // boss 通道的 handler
     .childHandler(new ChannelInitializer<SocketChannel>() {
         @Override
         protected void initChannel(SocketChannel ch) {
             ch.pipeline().addLast(new ServerHandler());
         }
     });

    ChannelFuture future = b.bind(8080).sync();
    future.channel().closeFuture().sync();
} finally {
    boss.shutdownGracefully();
    worker.shutdownGracefully();
}
```

## 4. ChannelHandler 和 ChannelPipeline

### 4.1 ChannelInboundHandler vs ChannelOutboundHandler

| | ChannelInboundHandler | ChannelOutboundHandler |
|--|----------------------|----------------------|
| 方向 | 入站（数据进入） | 出站（数据写出） |
| 触发方式 | 被动触发（数据到达） | 主动调用（write/flush） |
| 典型事件 | channelRead、channelActive、exceptionCaught | write、flush、close、connect |
| 执行顺序 | 正向（从头到尾） | 反向（从尾到头） |

```java
// 入站处理器常用方法
public class MyInboundHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRegistered(ChannelHandlerContext ctx) { }
    @Override
    public void channelActive(ChannelHandlerContext ctx) {
        System.out.println("连接已建立");
        ctx.fireChannelActive(); // 传播给下一个 handler
    }
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        System.out.println("收到数据: " + msg);
        ctx.fireChannelRead(msg); // 传播
    }
    @Override
    public void channelReadComplete(ChannelHandlerContext ctx) {
        ctx.flush(); // 批量写出
    }
    @Override
    public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
        cause.printStackTrace();
        ctx.close();
    }
    @Override
    public void channelInactive(ChannelHandlerContext ctx) {
        System.out.println("连接断开");
    }
}

// 出站处理器常用方法
public class MyOutboundHandler extends ChannelOutboundHandlerAdapter {
    @Override
    public void write(ChannelHandlerContext ctx, Object msg, ChannelPromise promise) {
        System.out.println("写出数据: " + msg);
        ctx.write(msg, promise); // 传播给下一个出站 handler
    }
    @Override
    public void flush(ChannelHandlerContext ctx) {
        ctx.flush();
    }
    @Override
    public void close(ChannelHandlerContext ctx, ChannelPromise promise) {
        System.out.println("关闭连接");
        ctx.close(promise);
    }
}
```

### 4.2 Handler 执行顺序详解

```
Pipeline 注册顺序:
  "decoder" → "encoder" → "businessHandler"
  (inbound)   (outbound)   (inbound)

入站事件（读数据）：
  decoder.read() → businessHandler.read()
  (encoder 是 outbound，入站跳过他)

出站事件（写数据）：
  businessHandler 调用 ctx.write()
  → encoder.write() → decoder.write()
  (decoder 是 inbound，出站跳过他)

重要规则：
1. ctx.write() 从当前 handler 往前（tail 方向）找最近的 outbound handler
2. ctx.channel().write() 从 pipeline 尾部开始传播
3. ctx.pipeline().writeAndFlush(msg) 也从尾部开始
4. ctx.fireChannelRead(msg) 向后传播给下一个 inbound handler
```

### 4.3 SimpleChannelInboundHandler 的使用

```java
// SimpleChannelInboundHandler<T> 自动释放资源
// 而 ChannelInboundHandlerAdapter 不会自动释放

// 推荐方式：使用 SimpleChannelInboundHandler
public class BusinessHandler extends SimpleChannelInboundHandler<String> {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, String msg) {
        // msg 已被解码为 String，处理完自动释放
        System.out.println("业务处理: " + msg);
        ctx.writeAndFlush("处理完成: " + msg);
    }
}

// 不推荐（手动麻烦）：ChannelInboundHandlerAdapter
public class ManualHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        try {
            String str = (String) msg;
            System.out.println(str);
            ctx.writeAndFlush("OK");
        } finally {
            // 必须手动释放引用计数对象
            ReferenceCountUtil.release(msg);
        }
    }
}
```

**区别总结**：

| 特性 | SimpleChannelInboundHandler | ChannelInboundHandlerAdapter |
|------|---------------------------|------------------------------|
| 泛型 | ✅ 支持泛型，自动转型 | ❌ Object 类型，需手动强转 |
| 资源释放 | ✅ channelRead0 执行后自动释放 | ❌ 不释放，需手动 ReferenceCountUtil.release |
| 适用场景 | 消息处理末端，业务逻辑 | 中间处理器（转发、编解码） |
| 推荐程度 | **强烈推荐** | 仅在需要控制传播时使用 |

### 4.4 Handler 的生命周期

```
Handler 的生命周期（按执行顺序）：

1. handlerAdded()     → Handler 被加入 Pipeline 时调用
2. channelRegistered() → Channel 注册到 EventLoop
3. channelActive()     → Channel 连接就绪（TCP 握手完成）
4. channelRead()       → 收到数据
5. channelReadComplete() → 一次读完成
   ... 业务处理 ...
6. channelInactive()   → Channel 连接断开
7. channelUnregistered() → Channel 从 EventLoop 注销
8. handlerRemoved()    → Handler 从 Pipeline 移除

exceptionCaught() 可在任意阶段触发
```

```java
public class LifecycleHandler extends ChannelInboundHandlerAdapter {
    private final String name;

    public LifecycleHandler(String name) {
        this.name = name;
    }

    @Override
    public void handlerAdded(ChannelHandlerContext ctx) {
        System.out.println(name + " 被添加到 Pipeline");
    }

    @Override
    public void channelRegistered(ChannelHandlerContext ctx) {
        System.out.println(name + " Channel 注册到 EventLoop");
        ctx.fireChannelRegistered();
    }

    @Override
    public void channelActive(ChannelHandlerContext ctx) {
        System.out.println(name + " 连接建立");
        ctx.fireChannelActive();
    }

    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        System.out.println(name + " 读取数据");
        ctx.fireChannelRead(msg);
    }

    @Override
    public void channelReadComplete(ChannelHandlerContext ctx) {
        System.out.println(name + " 读取完成");
        ctx.fireChannelReadComplete();
    }

    @Override
    public void channelInactive(ChannelHandlerContext ctx) {
        System.out.println(name + " 连接断开");
        ctx.fireChannelInactive();
    }

    @Override
    public void channelUnregistered(ChannelHandlerContext ctx) {
        System.out.println(name + " Channel 注销");
        ctx.fireChannelUnregistered();
    }

    @Override
    public void handlerRemoved(ChannelHandlerContext ctx) {
        System.out.println(name + " 从 Pipeline 移除");
    }

    @Override
    public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
        System.err.println(name + " 异常: " + cause.getMessage());
        ctx.close();
    }
}
```

### 5.2 粘包拆包问题与解决方案

#### 问题描述

**粘包**：多个消息被合并成一个包发送
**拆包**：一个消息被拆分成多个包发送

```
发送端：    [消息A]        [消息B]        [消息C]

TCP 传输：  [消息A消息B]    [消息C]        ← 粘包
或：        [消息A]        [消息B前一半] [消息B后一半消息C]  ← 拆包

原因：TCP 是流式协议，没有消息边界，上层应用需要自行界定消息边界
```

#### 方案 1：LineBasedFrameDecoder（换行符分割）

```java
// 以换行符 \n 或 \r\n 作为消息分隔符
ch.pipeline().addLast(new LineBasedFrameDecoder(1024)); // 最大 1024 字节
ch.pipeline().addLast(new StringDecoder());

// 客户端发送时每条消息末尾加 \n
ctx.writeAndFlush(Unpooled.copiedBuffer("Hello Server\n", CharsetUtil.UTF_8));
```

#### 方案 2：DelimiterBasedFrameDecoder（自定义分隔符）

```java
// 以自定义分隔符 `$$` 分割
ByteBuf delimiter = Unpooled.copiedBuffer("$$", CharsetUtil.UTF_8);
ch.pipeline().addLast(new DelimiterBasedFrameDecoder(1024, delimiter));
ch.pipeline().addLast(new StringDecoder());

// 发送：每条消息末尾加 $$
ctx.writeAndFlush(Unpooled.copiedBuffer("Hello$$World$$", CharsetUtil.UTF_8));
```

#### 方案 3：FixedLengthFrameDecoder（定长消息）

```java
// 每条消息固定 100 字节，不足则等待
ch.pipeline().addLast(new FixedLengthFrameDecoder(100));
ch.pipeline().addLast(new StringDecoder());

// 不足 100 字节时需补齐
byte[] data = "Hello".getBytes();
byte[] padded = new byte[100];
System.arraycopy(data, 0, padded, 0, data.length);
ctx.writeAndFlush(Unpooled.copiedBuffer(padded));
```

#### 方案 4：LengthFieldBasedFrameDecoder（包头+包体，最常用）

这是**最主流、最灵活**的粘包拆包解决方案。

```
协议格式：
┌───────────────┬───────────────┐
│  Length(4B)   │   Body(N B)   │
│  包体长度      │   消息内容     │
└───────────────┴───────────────┘

参数说明：
- maxFrameLength: 最大帧长度，防止恶意数据
- lengthFieldOffset: 长度字段偏移量（0 表示从包头开始）
- lengthFieldLength: 长度字段占用的字节数（通常 4）
- lengthAdjustment: 长度调整值（包头长度补偿）
- initialBytesToStrip: 解析后跳过的字节数（跳过包头）
```

```java
// 常见一：标准长度头（长度字段仅含 body 长度）
// 协议: [4字节长度][N字节消息]
ch.pipeline().addLast(new LengthFieldBasedFrameDecoder(
        65536,      // maxFrameLength: 最大帧长
        0,          // lengthFieldOffset: 长度字段偏移
        4,          // lengthFieldLength: 长度字段字节数
        0,          // lengthAdjustment: 长度调整
        4           // initialBytesToStrip: 跳过前4个字节（长度头本身）
));
ch.pipeline().addLast(new StringDecoder());

// 常见二：长度字段包含 body + header 自身
// 协议: [4字节总长度(含自身)][N字节消息]
ch.pipeline().addLast(new LengthFieldBasedFrameDecoder(
        65536, 0, 4, 0, 4
));

// 常见三：带有 Header 和 Body 的协议
// 协议: [version(1B)][type(1B)][length(4B)][body(N B)]
//       0            1           2           6
ch.pipeline().addLast(new LengthFieldBasedFrameDecoder(
        65536,          // maxFrameLength
        2,              // lengthFieldOffset: 从第 2 字节开始是长度
        4,              // lengthFieldLength: 长度占 4 字节
        -6,             // lengthAdjustment: 补偿 header 长度 (2+4-(2+4)=0...实际是 -6)
        6               // initialBytesToStrip: 跳过整个 header
));
```

### 5.3 自定义编解码器

```java
/**
 * 自定义协议：
 * ┌───────┬────────┬────────┐
 * │ magic │ length │  body  │
 * │ (4B)  │  (4B)  │ (N B)  │
 * └───────┴────────┴────────┘
 * magic = 0xCAFEBABE
 */

// ===== 自定义编码器 =====
public class MyEncoder extends MessageToByteEncoder<MyMessage> {
    @Override
    protected void encode(ChannelHandlerContext ctx, MyMessage msg, ByteBuf out) {
        // 写入魔数
        out.writeInt(0xCAFEBABE);
        // 获取 body 字节
        byte[] body = msg.getContent().getBytes(CharsetUtil.UTF_8);
        // 写入 body 长度
        out.writeInt(body.length);
        // 写入 body 内容
        out.writeBytes(body);
    }
}

// ===== 自定义解码器 =====
public class MyDecoder extends ByteToMessageDecoder {
    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) {
        // 检查头部是否完整（magic 4B + length 4B = 8B）
        if (in.readableBytes() < 8) {
            return; // 数据不够，等待下次
        }

        // 标记当前读指针位置
        in.markReaderIndex();

        int magic = in.readInt();
        if (magic != 0xCAFEBABE) {
            // 魔数不对，关闭连接
            ctx.close();
            return;
        }

        int bodyLength = in.readInt();

        // 检查 body 是否完整到达
        if (in.readableBytes() < bodyLength) {
            // body 还没到齐，重置指针，等待更多数据
            in.resetReaderIndex();
            return;
        }

        // 读取 body
        byte[] body = new byte[bodyLength];
        in.readBytes(body);
        String content = new String(body, CharsetUtil.UTF_8);

        // 将解析好的消息传给下一个 handler
        out.add(new MyMessage(content));
    }
}

// ===== 消息对象 =====
public class MyMessage {
    private final String content;

    public MyMessage(String content) {
        this.content = content;
    }

    public String getContent() {
        return content;
    }
}

// ===== Pipeline 配置 =====
ch.pipeline().addLast(new MyDecoder());
ch.pipeline().addLast(new MyEncoder());
ch.pipeline().addLast(new BusinessHandler());
```

## 6. Netty 高级特性

### 6.1 Bootstrap 的 option 和 childOption 配置

```java
ServerBootstrap b = new ServerBootstrap();
b.group(boss, worker)
 .channel(NioServerSocketChannel.class)

 // ===== boss 通道参数（ServerSocketChannel）=====
 .option(ChannelOption.SO_BACKLOG, 1024)         // accept 队列大小
 .option(ChannelOption.SO_REUSEADDR, true)       // 端口重用（快速重启）
 .option(ChannelOption.SO_RCVBUF, 256 * 1024)    // 接收缓冲区 256KB

 // ===== worker 通道参数（SocketChannel）=====
 .childOption(ChannelOption.TCP_NODELAY, true)   // 禁用 Nagle 算法
 .childOption(ChannelOption.SO_KEEPALIVE, true)  // TCP 心跳
 .childOption(ChannelOption.SO_SNDBUF, 128 * 1024)  // 发送缓冲区
 .childOption(ChannelOption.SO_RCVBUF, 128 * 1024)  // 接收缓冲区
 .childOption(ChannelOption.CONNECT_TIMEOUT_MILLIS, 5000) // 连接超时

 // ===== Netty 特有参数 =====
 .childOption(ChannelOption.WRITE_BUFFER_WATER_MARK,
         WriteBufferWaterMark.DEFAULT);          // 写缓冲区水位
```

### 6.2 关键参数详解

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `SO_BACKLOG` | 128 | TCP accept 队列大小，高并发时需增大。内核有两个队列：SYN 半连接队列 + accept 全连接队列，总和不超过此值 |
| `TCP_NODELAY` | false | 禁用 **Nagle 算法**。Nagle 会等待缓冲区积攒到 MSS 或收到 ACK 才发，导致交互式应用延迟大。**实时应用必须开启** |
| `SO_KEEPALIVE` | false | TCP 层心跳探测（默认 2 小时）。不如应用层心跳灵活，建议配合 `IdleStateHandler` 使用 |
| `SO_REUSEADDR` | false | 允许端口重用，特别是服务重启时避免"Address already in use" |
| `SO_RCVBUF` | 系统默认 | TCP 接收缓冲区大小，大值提高吞吐但延迟增加 |
| `SO_SNDBUF` | 系统默认 | TCP 发送缓冲区大小 |
| `CONNECT_TIMEOUT_MILLIS` | 30000 | 连接超时时间（毫秒） |
| `WRITE_BUFFER_WATER_MARK` | 32K / 64K | 写缓冲区水位线，低于 low 可写，高于 high 不可写（用于背压控制） |

```java
// Nagle 算法说明
// 启 Nagle：小包不立即发送，等凑够大小或收到前一个包 ACK 再发
//           → 吞吐高，延迟大（可能多 40ms）
// 禁 Nagle（TCP_NODELAY=true）：小包立即发送
//           → 延迟低，适合实时交互（游戏、IM、RPC）
```

### 6.4 断线重连实现

```java
public class ReconnectClient {
    private static final String HOST = "localhost";
    private static final int PORT = 8080;
    private static final int MAX_RETRIES = 5;
    private static final long RETRY_DELAY_MS = 3000;

    private final EventLoopGroup group = new NioEventLoopGroup();
    private volatile boolean running = true;

    public void start() {
        connectWithRetry(0);
    }

    private void connectWithRetry(int retryCount) {
        if (!running) return;

        Bootstrap b = new Bootstrap();
        b.group(group)
         .channel(NioSocketChannel.class)
         .option(ChannelOption.TCP_NODELAY, true)
         .handler(new ChannelInitializer<SocketChannel>() {
             @Override
             protected void initChannel(SocketChannel ch) {
                 ch.pipeline().addLast(
                         new IdleStateHandler(0, 4, 0, TimeUnit.SECONDS),
                         new ClientHeartbeatHandler(),
                         new ClientBusinessHandler());
             }
         });

        // 监听连接结果
        b.connect(HOST, PORT).addListener((ChannelFutureListener) future -> {
            if (future.isSuccess()) {
                System.out.println("连接成功");
                // 连接断开时自动触发重连
                future.channel().closeFuture().addListener(closeFuture -> {
                    System.out.println("连接断开，准备重连...");
                    connectWithRetry(0); // 重置重试计数
                });
            } else {
                if (retryCount < MAX_RETRIES) {
                    System.out.printf("连接失败 (第%d次重试) %n", retryCount + 1);
                    // 指数退避
                    long delay = RETRY_DELAY_MS * (long) Math.pow(2, retryCount);
                    future.channel().eventLoop().schedule(
                            () -> connectWithRetry(retryCount + 1),
                            delay, TimeUnit.MILLISECONDS);
                } else {
                    System.err.println("重试已达上限，停止连接");
                }
            }
        });
    }

    public void stop() {
        running = false;
        group.shutdownGracefully();
    }

    // 心跳处理器
    static class ClientHeartbeatHandler extends ChannelInboundHandlerAdapter {
        @Override
        public void userEventTriggered(ChannelHandlerContext ctx, Object evt) {
            if (evt instanceof IdleStateEvent
                    && ((IdleStateEvent) evt).state() == IdleState.WRITER_IDLE) {
                ctx.writeAndFlush("PING");
            }
        }
    }

    // 业务处理器
    static class ClientBusinessHandler extends SimpleChannelInboundHandler<String> {
        @Override
        protected void channelRead0(ChannelHandlerContext ctx, String msg) {
            System.out.println("服务端响应: " + msg);
        }

        @Override
        public void channelActive(ChannelHandlerContext ctx) {
            ctx.writeAndFlush("Hello Server");
        }
    }

    public static void main(String[] args) {
        ReconnectClient client = new ReconnectClient();
        client.start();
    }
}
```

### 6.5 ByteBuf 最佳实践

#### ByteBuf 结构

```
ByteBuf 是一个可扩容的字节缓冲区，读写分离指针：

        readableBytes     writableBytes
      ┌─────────────────┬─────────────────┐
      │  可读 (已写数据)  │  可写 (空闲空间)  │
      └─────────────────┴─────────────────┘
      ↑                 ↑                  ↑
    readerIndex       writerIndex        capacity

读取 3 字节后：
        ┌────────────┬───────────────────────┐
        │ 已读 (废弃) │  剩余可读 | 可写        │
        └────────────┴───────────────────────┘
      ↑             ↑                      ↑
    readerIndex   writerIndex            capacity
```

#### 池化 vs 非池化、堆内存 vs 直接内存

```java
// ===== 分配方式 =====

// 1. 池化直接内存（推荐，最高性能）

ByteBuf poolHeap = PooledByteBufAllocator.DEFAULT.heapBuffer(256);

// 3. Unpooled 工具类（方便测试，生产环境尽量避免）
ByteBuf buf1 = Unpooled.buffer(256);                  // 堆内存
ByteBuf buf2 = Unpooled.directBuffer(256);            // 直接内存
ByteBuf buf3 = Unpooled.copiedBuffer("Hello", CharsetUtil.UTF_8); // 从字符串创建
ByteBuf buf4 = Unpooled.wrappedBuffer(new byte[]{1,2,3});         // 包装数组（零拷贝）

// ===== 启用池化（Netty 4.x 默认开启）=====
// 启动参数：-Dio.netty.allocator.type=pooled    （默认）
// 启动参数：-Dio.netty.allocator.type=unpooled  （禁用池化）

// 池化优势：减少 GC 压力，重用 ByteBuf 对象，减少内存分配开销
```

#### ByteBuf 核心操作

```java
public class ByteBufExample {
    public static void main(String[] args) {
        ByteBuf buf = PooledByteBufAllocator.DEFAULT.buffer(10);

        // ===== 写操作 =====
        buf.writeByte(1);
        buf.writeShort(100);
        buf.writeInt(1000);
        buf.writeBytes("Hello".getBytes());
        buf.writeCharSequence("World", CharsetUtil.UTF_8);

        // ===== 读操作 =====
        byte b = buf.readByte();
        short s = buf.readShort();
        int i = buf.readInt();
        byte[] dst = new byte[5];
        buf.readBytes(dst);
        CharSequence cs = buf.readCharSequence(5, CharsetUtil.UTF_8);

        // ===== 随机访问（不影响指针）=====
        byte first = buf.getByte(0);
        int val = buf.getInt(4);

        // ===== 其他操作 =====
        buf.markReaderIndex();      // 标记读位置
        buf.readByte();
        buf.resetReaderIndex();     // 恢复到标记位置

        buf.writerIndex(0);         // 重置写指针
        buf.clear();                // 重置读写指针
        buf.discardReadBytes();     // 回收已读空间（可能触发内存复制）

        // ===== 零拷贝操作 =====
        ByteBuf slice = buf.slice(0, 5);          // 切片（共享内存）
        ByteBuf duplicate = buf.duplicate();       // 复制整个缓冲区（共享内存）
        ByteBuf copy = buf.copy(0, 5);            // 真正复制（独立内存）

        // ===== 引用计数（池化必须手动释放）=====
        buf.retain();    // 引用计数 +1
        buf.release();   // 引用计数 -1，归零则归还池中
        int refCnt = buf.refCnt();

        // SimpleChannelInboundHandler 会自动 release
        // 如果手动持有 ByteBuf，用完必须 release

        // 清理
        buf.release();
    }
}
```

#### 最佳实践总结

| 实践 | 说明 |
|------|------|
| **开启池化** | 默认已开启，显式配置 `-Dio.netty.allocator.type=pooled` |
| **使用直接内存** | `PooledByteBufAllocator.DEFAULT.directBuffer()`，减少用户态与内核态拷贝 |
| **用完释放** | 每 `retain()` 必须有对应的 `release()`，或让 SimpleChannelInboundHandler 自动管理 |
| **避免在业务线程中持有 ByteBuf** | 业务线程应解码为 POJO 再处理 |
| **优先零拷贝** | `slice()`、`duplicate()`、`CompositeByteBuf` 避免内存复制 |
| **配置 Arena 数量** | `-Dio.netty.allocator.numHeapArenas` / `numDirectArenas` 设置为 CPU 核心数 × 2 |

```java
public class RpcRequest implements Serializable {
    private String className;      // 接口全路径
    private String methodName;     // 方法名
    private Class<?>[] paramTypes; // 参数类型
    private Object[] params;       // 参数值

    // getter / setter / constructor 省略
}

public class RpcResponse implements Serializable {
    private Object result;         // 返回值
    private Throwable error;       // 异常

    // getter / setter 省略
}

// ===== 2. 公共编解码器 =====
public class RpcEncoder extends MessageToByteEncoder<RpcRequest> {
    @Override
    protected void encode(ChannelHandlerContext ctx, RpcRequest msg, ByteBuf out) {
        try {
            ByteArrayOutputStream baos = new ByteArrayOutputStream();
            ObjectOutputStream oos = new ObjectOutputStream(baos);
            oos.writeObject(msg);
            oos.flush();
            byte[] data = baos.toByteArray();

            // 协议：长度(4B) + 数据(N B)
            out.writeInt(data.length);
            out.writeBytes(data);
        } catch (IOException e) {
            throw new RuntimeException("RPC 编码失败", e);
        }
    }
}

public class RpcDecoder extends ByteToMessageDecoder {
    private final Class<?> targetClass;

    public RpcDecoder(Class<?> targetClass) {
        this.targetClass = targetClass;
    }

    @Override
    protected void decode(ChannelHandlerContext ctx, ByteBuf in, List<Object> out) throws Exception {
        if (in.readableBytes() < 4) return;
        in.markReaderIndex();
        int length = in.readInt();
        if (in.readableBytes() < length) {
            in.resetReaderIndex();
            return;
        }
        byte[] data = new byte[length];
        in.readBytes(data);
        ByteArrayInputStream bais = new ByteArrayInputStream(data);
        ObjectInputStream ois = new ObjectInputStream(bais);
        out.add(ois.readObject());
    }
}

// 服务注册表
public class ServiceRegistry {
    private static final Map<String, Object> SERVICES = new ConcurrentHashMap<>();

    public static void register(Class<?> interfaceClass, Object serviceImpl) {
        SERVICES.put(interfaceClass.getName(), serviceImpl);
    }

    public static Object get(String className) {
        return SERVICES.get(className);
    }
}

// 服务端处理器
public class RpcServerHandler extends SimpleChannelInboundHandler<RpcRequest> {
    @Override
    protected void channelRead0(ChannelHandlerContext ctx, RpcRequest req) {
        RpcResponse resp = new RpcResponse();
        try {
            Object service = ServiceRegistry.get(req.getClassName());
            Method method = service.getClass()
                    .getMethod(req.getMethodName(), req.getParamTypes());
            Object result = method.invoke(service, req.getParams());
            resp.setResult(result);
        } catch (Exception e) {
            resp.setError(e);
        }
        ctx.writeAndFlush(resp);
    }
}

public class RpcClientProxy {
    @SuppressWarnings("unchecked")
    public static <T> T create(Class<T> interfaceClass, String host, int port) {
        return (T) Proxy.newProxyInstance(
                interfaceClass.getClassLoader(),
                new Class<?>[]{interfaceClass},
                new RpcInvocationHandler(host, port));
    }

    static class RpcInvocationHandler implements InvocationHandler {
        private final String host;
        private final int port;

        RpcInvocationHandler(String host, int port) {
            this.host = host;
            this.port = port;
        }

        @Override
        public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
            RpcRequest req = new RpcRequest();
            req.setClassName(method.getDeclaringClass().getName());
            req.setMethodName(method.getName());
            req.setParamTypes(method.getParameterTypes());
            req.setParams(args);

            // 每个调用一个连接（实际应用应使用连接池）
            EventLoopGroup group = new NioEventLoopGroup();
            try {
                RpcClientHandler handler = new RpcClientHandler();
                Bootstrap b = new Bootstrap();
                b.group(group)
                 .channel(NioSocketChannel.class)
                 .handler(new ChannelInitializer<SocketChannel>() {
                     @Override
                     protected void initChannel(SocketChannel ch) {
                         ch.pipeline().addLast(
                                 new RpcDecoder(RpcResponse.class),
                                 new RpcEncoder(),
                                 handler);
                     }
                 });
                ChannelFuture future = b.connect(host, port).sync();
                future.channel().writeAndFlush(req).sync();
                future.channel().closeFuture().sync();
                return handler.getResponse().getResult();
            } finally {
                group.shutdownGracefully();
            }
        }
    }
}
```

```java
        // 构建 HTML 响应体
        String content = String.format(
                new String(HTML), req.uri(), req.method().name());

        // 构建响应
        FullHttpResponse resp = new DefaultFullHttpResponse(
                HttpVersion.HTTP_1_1,
                HttpResponseStatus.OK,
                Unpooled.wrappedBuffer(content.getBytes()));

        // 设置响应头
        resp.headers()
            .set(HttpHeaderNames.CONTENT_TYPE, "text/html; charset=utf-8")
            .set(HttpHeaderNames.CONTENT_LENGTH, resp.content().readableBytes());

        // 如果是 keep-alive 连接，添加相应头
        if (HttpUtil.isKeepAlive(req)) {
            resp.headers().set(HttpHeaderNames.CONNECTION, HttpHeaderValues.KEEP_ALIVE);
        }

        ctx.writeAndFlush(resp);
    }

    @Override
    public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
        cause.printStackTrace();
        ctx.close();
    }
}
```

## 8. 性能优化与最佳实践

### 8.1 内存泄漏检测

Netty 提供了 ByteBuf 内存泄漏检测机制，通过系统属性配置检测级别。

```java
// 启动参数配置
// -Dio.netty.leakDetectionLevel=disabled    — 关闭检测（最高性能，不推荐）
// -Dio.netty.leakDetectionLevel=simple      — 抽样检测（约 1%），发现泄漏打印日志
// -Dio.netty.leakDetectionLevel=advanced    — 抽样检测 + 记录泄漏现场（创建栈）
// -Dio.netty.leakDetectionLevel=paranoid    — 每次分配都检测（最严格，性能下降严重）

// 生产环境推荐：-Dio.netty.leakDetectionLevel=advanced

// 日志输出示例（泄漏时）：
// WARN: LEAK: ByteBuf.release() was not called before it's garbage-collected.
// Recent access records:
// Created at:
//     io.netty.buffer.PooledByteBufAllocator.newDirectBuffer(...)
//     io.netty.buffer.AbstractByteBufAllocator.directBuffer(...)
//     ...
```

**泄漏排查步骤**：

```java
// 1. 启用高级检测
// -Dio.netty.leakDetectionLevel=advanced

// 2. 触发生成 Heap Dump
// jmap -dump:format=b,file=netty.hprof <pid>

// 3. 分析 ByteBuf 被哪些对象引用

// 4. 常见泄漏原因：
//    a. SimpleChannelInboundHandler 以外的 handler 未释放 msg
//    b. 业务线程持有 ByteBuf 未 release
//    c. 异常分支忘记 release
//    d. retain() 和 release() 不匹配

// 常见错误示例
public class LeakyHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        ByteBuf buf = (ByteBuf) msg;
        byte[] data = new byte[buf.readableBytes()];
        buf.readBytes(data);
        // ❌ 没有释放 buf（池化 ByteBuf 会泄漏）
        // ❌ 也没有调用 ctx.fireChannelRead(msg)
        ctx.writeAndFlush(data);
    }
}

// 正确写法
public class CorrectHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        ByteBuf buf = (ByteBuf) msg;
        try {
            byte[] data = new byte[buf.readableBytes()];
            buf.readBytes(data);
            ctx.writeAndFlush(data);
        } finally {
            // ✅ 确保释放
            ReferenceCountUtil.release(buf);
        }
    }
}
```

### 8.2 线程模型选择

| 场景 | 推荐模型 | 说明 |
|------|---------|------|
| 纯计算密集型服务 | Boss=1, Worker=CPU×2 | Worker 业务时间短，不需要额外线程池 |
| IO 密集型服务（DB 调用） | Boss=1, Worker=CPU×2, +业务线程池 | Worker 只做 IO，业务交给业务线程池 |
| 长连接推送服务 | Boss=1, Worker=CPU×2 | 连接多但消息量不大，心跳为主 |
| 文件传输服务 | Boss=1, Worker=CPU×2, +FileRegion | 利用零拷贝，Worker 只做通道管理 |
| 网关服务 | Boss=1, Worker=CPU×2 | 转发为主，计算量小 |

```java
// ===== 推荐配置 =====
public class ThreadModelConfig {

    // 1. 纯 IO 处理（最常用）
    EventLoopGroup boss = new NioEventLoopGroup(1);
    EventLoopGroup worker = new NioEventLoopGroup();

    // 2. 业务线程池（当业务有阻塞操作时）
    static final ExecutorService BUSINESS_POOL =
            new ThreadPoolExecutor(
                    16, 32, 60, TimeUnit.SECONDS,
                    new LinkedBlockingQueue<>(10000),
                    new ThreadFactoryBuilder().setNameFormat("business-%d").build(),
                    new ThreadPoolExecutor.CallerRunsPolicy());

    // 在 Handler 中使用：
    public class BusinessHandler extends SimpleChannelInboundHandler<String> {
        @Override
        protected void channelRead0(ChannelHandlerContext ctx, String msg) {
            BUSINESS_POOL.submit(() -> {
                // 阻塞业务（DB/Redis/RPC 调用）
                String result = callRemoteService(msg);
                ctx.writeAndFlush(result);
            });
        }

        private String callRemoteService(String msg) {
            // 模拟阻塞调用
            try { Thread.sleep(100); } catch (InterruptedException ignored) {}
            return "Processed: " + msg;
        }
    }
}
```

### 8.3 参数调优建议

```java
// ===== 全面优化配置的服务端 =====
public class OptimizedServer {
    public static void main(String[] args) {
        // 系统属性配置（程序入口设置）
        System.setProperty("io.netty.allocator.type", "pooled");
        System.setProperty("io.netty.leakDetectionLevel", "advanced");
        System.setProperty("io.netty.noUnsafe", "false");    // 启用 Unsafe（更高性能）
        System.setProperty("io.netty.eventLoopThreads", String.valueOf(
                Runtime.getRuntime().availableProcessors() * 2));

        EventLoopGroup boss = new NioEventLoopGroup(1);
        EventLoopGroup worker = new NioEventLoopGroup();
        try {
            ServerBootstrap b = new ServerBootstrap();
            b.group(boss, worker)
             .channel(NioServerSocketChannel.class)

             // ===== 服务端参数 =====
             .option(ChannelOption.SO_BACKLOG, 1024)
             .option(ChannelOption.SO_REUSEADDR, true)

             // ===== 子通道参数 =====
             .childOption(ChannelOption.TCP_NODELAY, true)
             .childOption(ChannelOption.SO_KEEPALIVE, true)
             .childOption(ChannelOption.SO_RCVBUF, 256 * 1024)
             .childOption(ChannelOption.SO_SNDBUF, 256 * 1024)

             // ===== Netty 参数 =====
             .childOption(ChannelOption.WRITE_BUFFER_WATER_MARK,
                     new WriteBufferWaterMark(32 * 1024, 64 * 1024))
             .childOption(ChannelOption.ALLOCATOR,
                     PooledByteBufAllocator.DEFAULT)          // 池化分配器
             .childOption(ChannelOption.RCVBUF_ALLOCATOR,
                     AdaptiveRecvByteBufAllocator.DEFAULT)    // 自适应接收缓冲区

             .childHandler(new ChannelInitializer<SocketChannel>() {
                 @Override
                 protected void initChannel(SocketChannel ch) {
                     ch.pipeline()
                         .addLast(new LengthFieldBasedFrameDecoder(65536, 0, 4, 0, 4))
                         .addLast(new StringDecoder())
                         .addLast(new BusinessHandler());
                 }
             })
             .bind(8080).sync()
             .channel().closeFuture().sync();
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            boss.shutdownGracefully();
            worker.shutdownGracefully();
        }
    }
}
```

#### 调优参数总结

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `SO_BACKLOG` | 1024 ~ 65536 | 根据并发连接数调整，吞吐越高值越大 |
| `TCP_NODELAY` | true | 禁用 Nagle，实时通信必须开启 |
| `SO_KEEPALIVE` | true | 配合 IdleStateHandler 应用层心跳 |
| `SO_RCVBUF` | 256KB ~ 1MB | 增大提高大包吞吐，减小降低小包延迟 |
| `SO_SNDBUF` | 256KB ~ 1MB | 同接收缓冲区 |
| `WRITE_BUFFER_WATER_MARK` | low=32K, high=64K | 默认已较合理，高吞吐场景可放大 |
| `io.netty.allocator.maxOrder` | 9 (默认) | 越大池化内存块越大，碎片越少但浪费增多 |
| `EventLoop 线程数` | CPU × 2 | 纯 IO 处理场景；有阻塞业务需要额外业务线程池 |
| `ALLOCATOR` | PooledByteBufAllocator | 池化+直接内存，IO 密集型最佳选择 |

### 常见问题 FAQ

| 问题 | 答案 |
|------|------|
| Netty 4.x 还是 5.x？ | 5.x 已废弃，使用 **4.1.x** |
| NIO 还是 epoll？ | Linux 下优先使用 EpollEventLoopGroup（需 netty-transport-native-epoll） |
| 直接内存还是堆内存？ | **直接内存**，减少一次拷贝 |
| BIO 还是 NIO？ | 永远选 NIO |
| AIO 现在能用吗？ | **不推荐**，Netty 已弃用 AIO 支持 |
| RPC 框架选型？ | 自研用 Netty，大厂方案选 Dubbo / gRPC / Thrift |
| handler 共享要注意什么？ | 用 `@Sharable` 注解，否则每个 Channel 需要新实例 |
| ChannelHandler 线程安全吗？ | 默认不是 `@Sharable` 的，一个 handler 实例只能绑定一个 EventLoop |
