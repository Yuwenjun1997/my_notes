# 4.1 CI/CD 流程搭建

> 本文档涵盖 CI/CD 核心概念、GitHub Actions 与 Jenkins Pipeline 实战、SonarQube 代码质量门禁、制品管理以及自动化测试集成。

---

## 一、CI/CD 概念

### 1.1 持续集成（Continuous Integration）

持续集成是一种软件开发实践，要求开发人员频繁地将代码变更合并到主干分支（通常每天多次）。每次合并都会触发**自动构建**和**自动测试**，从而尽早发现集成问题。

核心流程：

```
开发者提交代码 (git push)
       |
       v
代码仓库触发 Webhook
       |
       v
CI 服务器拉取代码
       |
       v
编译构建 (mvn/gradle compile)
       |
       v
自动测试 (单元测试 + 集成测试)
       |
       v
静态代码分析 (SonarQube)
       |
       v
生成制品 (jar/war/docker image)
```

### 1.2 持续部署（Continuous Deployment）

持续部署在持续集成的基础上更进一步，将通过自动化测试的代码**自动部署到生产环境**，无需人工干预。

```
CI 完成 -> 制品就绪
       |
       v
自动部署到开发环境 (dev)
       |
       v
冒烟测试通过
       |
       v
自动部署到预发布环境 (staging)
       |
       v
集成测试/E2E 测试通过
       |
       v
自动部署到生产环境 (prod)
       |
       v
健康检查 + 监控告警
```

### 1.3 传统部署 vs CI/CD 对比

| 维度 | 传统部署 | CI/CD |
|------|---------|-------|
| 集成频率 | 几天/几周一次 | 每天多次 |
| 构建方式 | 手动触发，本地构建 | 自动触发，服务器构建 |
| 测试覆盖 | 手动测试为主 | 自动化测试为主 |
| 部署方式 | 人工上传包、停机部署 | 自动发布、滚动更新 |
| 回滚速度 | 分钟/小时级 | 秒/分钟级 |
| 反馈周期 | 长（发现问题时已集成多日） | 短（每次提交立即反馈） |
| 质量门禁 | 人工 Review | 自动化门禁（测试覆盖/代码质量） |
| 环境一致性 | 开发/生产环境差异大 | 容器化保证环境一致 |

## 二、GitHub Actions 实战

### 2.1 完整配置 `.github/workflows/ci.yml`

```yaml
name: CI Pipeline

# ============ 触发条件 ============
on:
  push:
    branches: [main, develop, release/**]
    paths-ignore:
      - '**.md'
      - 'docs/**'
  pull_request:
    branches: [main, develop]
  schedule:
    # 每天凌晨 6:00 定时执行
    - cron: '0 6 * * *'
  workflow_dispatch:    # 手动触发

# ============ 环境变量 ============
env:
  REGISTRY: harbor.example.com
  IMAGE_NAME: myapp
  JAVA_VERSION: '17'
  MAVEN_OPTS: '-Dmaven.repo.local=${{ github.workspace }}/.m2/repository'

# ============ 并发控制 ============
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  # ---------- Job 1: 代码编译 ----------
  compile:
    name: Compile
    runs-on: ubuntu-22.04
    outputs:
      version: ${{ steps.set-version.outputs.version }}

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0    # 获取完整 git 历史，用于 SonarQube 分析

      - name: Set up JDK ${{ env.JAVA_VERSION }}
        uses: actions/setup-java@v4
        with:
          java-version: ${{ env.JAVA_VERSION }}
          distribution: 'temurin'
          cache: 'maven'    # 缓存 Maven 依赖

      - name: Compile
        run: |
          ./mvnw compile -DskipTests -q

      - name: Set version
        id: set-version
        run: |
          echo "version=$(./mvnw help:evaluate -Dexpression=project.version -q -DforceStdout)" >> $GITHUB_OUTPUT

  # ---------- Job 2: 单元测试 + 集成测试 ----------
  test:
    name: Test
    needs: compile
    runs-on: ubuntu-22.04

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up JDK ${{ env.JAVA_VERSION }}
        uses: actions/setup-java@v4
        with:
          java-version: ${{ env.JAVA_VERSION }}
          distribution: 'temurin'
          cache: 'maven'

      - name: Run Unit Tests
        run: ./mvnw test -Dtest="*Test" -DfailIfNoTests=false

      - name: Run Integration Tests
        run: ./mvnw verify -DskipUnitTests=true

      - name: Publish Test Report
        uses: dorny/test-reporter@v1
        if: always()
        with:
          name: Test Report
          path: '**/target/surefire-reports/*.xml'
          reporter: java-junit
          fail-on-error: false

  # ---------- Job 3: 静态代码分析 (SonarQube) ----------
  sonarqube:
    name: SonarQube Analysis
    needs: compile
    runs-on: ubuntu-22.04

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Set up JDK ${{ env.JAVA_VERSION }}
        uses: actions/setup-java@v4
        with:
          java-version: ${{ env.JAVA_VERSION }}
          distribution: 'temurin'
          cache: 'maven'

      - name: SonarQube Scan
        env:
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
        run: |
          ./mvnw sonar:sonar \
            -Dsonar.projectKey=myapp \
            -Dsonar.host.url=$SONAR_HOST_URL \
            -Dsonar.login=$SONAR_TOKEN \
            -Dsonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml

  # ---------- Job 4: 安全扫描 ----------
  security:
    name: Security Scan
    needs: compile
    runs-on: ubuntu-22.04

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up JDK ${{ env.JAVA_VERSION }}
        uses: actions/setup-java@v4
        with:
          java-version: ${{ env.JAVA_VERSION }}
          distribution: 'temurin'
          cache: 'maven'

      - name: OWASP Dependency Check
        run: ./mvnw org.owasp:dependency-check-maven:check

      - name: Trivy vulnerability scan
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: 'fs'
          scan-ref: '.'
          format: 'sarif'
          output: 'trivy-results.sarif'

      - name: Upload Trivy results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: 'trivy-results.sarif'

  # ---------- Job 5: 打包与 Docker 镜像构建 ----------
  package:
    name: Package & Docker Build
    needs: [test, sonarqube, security]
    runs-on: ubuntu-22.04
    if: github.ref == 'refs/heads/main'

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up JDK ${{ env.JAVA_VERSION }}
        uses: actions/setup-java@v4
        with:
          java-version: ${{ env.JAVA_VERSION }}
          distribution: 'temurin'
          cache: 'maven'

      - name: Build JAR
        run: ./mvnw package -DskipTests

      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Harbor
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ secrets.HARBOR_USERNAME }}
          password: ${{ secrets.HARBOR_PASSWORD }}

      - name: Extract metadata for Docker
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=sha,prefix=,format=short
            type=ref,event=branch
            type=raw,value=latest,enable=${{ github.ref == 'refs/heads/main' }}

      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ---------- Job 6: 多环境部署 ----------
  deploy-dev:
    name: Deploy to Dev
    needs: package
    runs-on: ubuntu-22.04
    environment: dev

    steps:
      - name: Deploy to Dev k8s cluster
        run: |
          # 使用 kubectl apply -f 部署到 dev 命名空间
          echo "Deploying to dev namespace..."

  deploy-staging:
    name: Deploy to Staging
    needs: deploy-dev
    runs-on: ubuntu-22.04
    environment: staging

    steps:
      - name: Deploy to Staging k8s cluster
        run: |
          echo "Deploying to staging namespace..."

  deploy-prod:
    name: Deploy to Production
    needs: deploy-staging
    runs-on: ubuntu-22.04
    environment:
      name: production
      url: https://myapp.example.com

    steps:
      - name: Deploy to Production k8s cluster
        run: |
          echo "Deploying to production namespace..."
```

### 2.2 关键配置说明

**触发条件**：
- `push`：代码推送到 main/develop/release 分支时触发
- `pull_request`：PR 创建或更新时触发
- `schedule`：定时执行（如每日凌晨全量检查）
- `workflow_dispatch`：支持手动触发

**并行 Job 依赖关系**：

```
                compile
              /    |    \
             /     |     \
            /      |      \
        test   sonarqube  security
            \      |      /
             \     |     /
              \    |    /
               package
                  |
              deploy-dev
                  |
            deploy-staging
                  |
              deploy-prod
```

**依赖缓存**：`actions/setup-java` 的 `cache: 'maven'` 自动缓存 `~/.m2/repository`，加速后续构建。

## 三、Jenkins Pipeline

### 3.1 Jenkinsfile 声明式语法完整示例

```groovy
// Jenkinsfile (Declarative Pipeline)
pipeline {
    agent any

    // ============ 参数化构建 ============
    parameters {
        choice(
            name: 'BUILD_ENV',
            choices: ['dev', 'staging', 'prod'],
            description: '选择部署环境'
        )
        string(
            name: 'BUILD_TAG',
            defaultValue: '',
            description: '自定义镜像标签（留空则自动生成）'
        )
        booleanParam(
            name: 'SKIP_TESTS',
            defaultValue: false,
            description: '是否跳过测试'
        )
    }

    // ============ 环境变量 ============
    environment {
        HARBOR_REGISTRY = 'harbor.example.com'
        IMAGE_NAME      = 'myapp'
        DOCKER_TAG      = "${params.BUILD_TAG ?: "${env.BUILD_NUMBER}-${env.GIT_COMMIT.take(7)}"}"
        MAVEN_OPTS      = '-Xmx2g -XX:MaxMetaspaceSize=512m'
    }

    // ============ 选项设置 ============
    options {
        timestamps()                       // 日志加时间戳
        buildDiscarder(logRotator(numToKeepStr: '10'))  // 保留最近 10 个构建
        timeout(time: 30, unit: 'MINUTES') // 超时 30 分钟
        retry(1)                           // 失败重试 1 次
    }

    stages {
        // ---- Stage 1: 代码检出 ----
        stage('Checkout') {
            steps {
                checkout([
                    $class: 'GitSCM',
                    branches: [[name: '*/main']],
                    userRemoteConfigs: [[url: 'https://github.com/example/myapp.git',
                                         credentialsId: 'github-ssh']],
                    extensions: [[$class: 'CleanBeforeCheckout'],
                                 [$class: 'CloneOption', depth: 0]]
                ])
            }
        }

        // ---- Stage 2: 编译 ----
        stage('Build') {
            steps {
                sh '''
                    ./mvnw clean compile -DskipTests -q
                '''
            }
            post {
                failure {
                    notifyBuildFailure('Compile failed')
                }
            }
        }

        // ---- Stage 3: 单元测试 + 集成测试 ----
        stage('Test') {
            when {
                expression { !params.SKIP_TESTS }
            }
            steps {
                sh '''
                    ./mvnw test -Dtest="*Test"
                    ./mvnw verify -DskipUnitTests=true
                '''
            }
            post {
                always {
                    junit allowEmptyResults: true,
                          testResults: '**/target/surefire-reports/*.xml'
                    // 生成 JaCoCo 覆盖率报告
                    jacoco(
                        execPattern: '**/target/*.exec',
                        classPattern: '**/classes',
                        sourcePattern: '**/src/main/java'
                    )
                }
            }
        }

        // ---- Stage 4: SonarQube 代码质量分析 ----
        stage('SonarQube') {
            steps {
                withSonarQubeEnv('SonarQube') {
                    sh '''
                        ./mvnw sonar:sonar \
                            -Dsonar.projectKey=myapp \
                            -Dsonar.host.url=${SONAR_HOST_URL} \
                            -Dsonar.login=${SONAR_AUTH_TOKEN} \
                            -Dsonar.coverage.jacoco.xmlReportPaths=target/site/jacoco/jacoco.xml
                    '''
                }
            }
        }

        // ---- Stage 5: OWASP 依赖安全检查 ----
        stage('Security Scan') {
            steps {
                sh '''
                    ./mvnw org.owasp:dependency-check-maven:check \
                        -Dformat=JSON
                '''
            }
            post {
                always {
                    dependencyCheckPublisher pattern: '**/dependency-check-report.json'
                }
            }
        }

        // ---- Stage 6: 构建 Docker 镜像 ----
        stage('Docker Build') {
            steps {
                sh '''
                    docker build -t ${HARBOR_REGISTRY}/${IMAGE_NAME}:${DOCKER_TAG} .
                    docker tag ${HARBOR_REGISTRY}/${IMAGE_NAME}:${DOCKER_TAG} \
                               ${HARBOR_REGISTRY}/${IMAGE_NAME}:latest
                '''
            }
        }

        // ---- Stage 7: 推送 Docker 镜像到 Harbor ----
        stage('Docker Push') {
            steps {
                withDockerRegistry([credentialsId: 'harbor-cred', url: "https://${HARBOR_REGISTRY}"]) {
                    sh '''
                        docker push ${HARBOR_REGISTRY}/${IMAGE_NAME}:${DOCKER_TAG}
                        docker push ${HARBOR_REGISTRY}/${IMAGE_NAME}:latest
                    '''
                }
            }
        }

        // ---- Stage 8: 部署到 Kubernetes ----
        stage('Deploy') {
            when {
                expression { params.BUILD_ENV == 'dev' || params.BUILD_ENV == 'staging' }
            }
            steps {
                script {
                    sh """
                        sed -i 's|\\\${IMAGE_TAG}|${DOCKER_TAG}|g' k8s/${params.BUILD_ENV}/deployment.yaml
                        kubectl apply -f k8s/${params.BUILD_ENV}/ --namespace=${params.BUILD_ENV}
                        kubectl rollout status deployment/myapp --namespace=${params.BUILD_ENV}
                    """
                }
            }
            post {
                success {
                    echo "Deploy to ${params.BUILD_ENV} succeeded!"
                }
                failure {
                    echo "Deploy to ${params.BUILD_ENV} failed, rolling back..."
                    sh "kubectl rollout undo deployment/myapp --namespace=${params.BUILD_ENV}"
                }
            }
        }
    }

    // ============ 构建后处理 ============
    post {
        always {
            cleanWs()  // 清理工作空间
        }
        success {
            notifyBuildSuccess()
        }
        failure {
            notifyBuildFailure('Pipeline failed')
        }
    }
}

// ============ 通知函数 ============
def notifyBuildSuccess() {
    // 发送企业微信/钉钉/邮件通知
    echo "Build successful!"
}

def notifyBuildFailure(String reason) {
    // 发送失败告警
    echo "Build failed: ${reason}"
}
```

### 3.2 与 Kubernetes 集成

```groovy
// k8s 部署脚本（在 Deploy Stage 中调用）
def deployToK8s(String env, String imageTag) {
    sh """
        # 替换 deployment.yaml 中的镜像标签
        sed -i 's|image:.*|image: ${HARBOR_REGISTRY}/${IMAGE_NAME}:${imageTag}|g' k8s/${env}/deployment.yaml

        # 应用配置
        kubectl apply -f k8s/${env}/ --namespace=${env}

        # 监控部署状态
        kubectl rollout status deployment/myapp \
            --namespace=${env} \
            --timeout=120s
    """
}

// 金丝雀发布（如果需要）
def canaryDeploy(String env, String imageTag) {
    sh """
        # 创建金丝雀版本
        kubectl set image deployment/myapp-canary \
            myapp=${HARBOR_REGISTRY}/${IMAGE_NAME}:${imageTag} \
            --namespace=${env}

        # 等待金丝雀就绪
        kubectl rollout status deployment/myapp-canary \
            --namespace=${env} --timeout=60s

        # 逐步切换流量（假设使用 Service Mesh）
        # ... istioctl 或 flagger 指令
    """
}
```

### 4.2 质量门禁配置

SonarQube 质量门禁（Quality Gate）是一组条件规则，只有满足所有条件才能通过门禁。

在 SonarQube UI 中配置的质量门禁示例：

| 指标 | 条件 | 阈值 | 说明 |
|------|------|------|------|
| 新增代码覆盖率 | 小于 | 80% | 新代码覆盖率不低于 80% |
| 整体代码覆盖率 | 小于 | 60% | 整体覆盖率不低于 60% |
| 新增 Bug | 大于 | 0 | 不允许引入新的 Bug |
| 新增漏洞 | 大于 | 0 | 不允许引入新的安全漏洞 |
| 新增代码异味 | 大于 | 0 | 不允许引入新的代码异味（A 级以上可放宽） |
| 重复率 | 大于 | 3% | 新增代码重复率不超过 3% |
| 可靠性评级 | 劣于 | C | 可靠性评级不低于 C |
| 安全评级 | 劣于 | C | 安全评级不低于 C |
| 可维护性评级 | 劣于 | C | 可维护性评级不低于 C |

### 4.3 代码问题分类

| 类型 | 严重级别 | 说明 | 示例 |
|------|---------|------|------|
| Bug | Blocker/Critical | 可能导致程序崩溃、数据丢失的缺陷 | 空指针异常、资源未关闭 |
| 漏洞 | Blocker/Critical | 存在安全风险 | SQL 注入、XSS、硬编码密码 |
| 代码异味 | Major/Minor | 代码可维护性问题，长期会积累技术债务 | 过长方法、循环复杂度高 |

常见问题示例：

```java
// Bug 示例：可能导致 NPE
public String getName(User user) {
    return user.getName().toUpperCase(); // 若 user 或 getName() 为 null 则 NPE
}

// 修复
public String getName(User user) {
    if (user == null || user.getName() == null) {
        return "";
    }
    return user.getName().toUpperCase();
}

// 代码异味示例：循环复杂度高
public String getStatus(int code) {
    if (code == 1) return "Pending";
    else if (code == 2) return "Processing";
    else if (code == 3) return "Shipped";
    else if (code == 4) return "Completed";
    else return "Unknown";
}

// 修复：使用 switch 表达式或枚举
public String getStatus(int code) {
    return switch (code) {
        case 1 -> "Pending";
        case 2 -> "Processing";
        case 3 -> "Shipped";
        case 4 -> "Completed";
        default -> "Unknown";
    };
}

// 安全漏洞：SQL 注入
// 错误写法
String sql = "SELECT * FROM users WHERE name = '" + userName + "'";

// 正确写法
String sql = "SELECT * FROM users WHERE name = ?";
// 使用 PreparedStatement
```

## 五、制品管理

### 5.1 Maven 私服（Nexus）

**Nexus Repository Manager** 用于管理 Maven 构建产物，分为三种仓库类型：

| 仓库类型 | 用途 | 说明 |
|---------|------|------|
| hosted | 宿主仓库 | 存储内部私有依赖和发布版制品 |
| proxy | 代理仓库 | 代理 Maven Central、JCenter 等公共仓库，缓存依赖 |
| group | 组合仓库 | 将多个仓库组合成一个地址对外暴露 |

Maven `settings.xml` 配置：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.0.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.0.0
```

### 5.2 Docker Registry（Harbor）

**Harbor** 是一个企业级的 Docker Registry，提供镜像管理、安全扫描、多租户等功能。

```bash
# 1. 登录 Harbor
docker login harbor.example.com -u admin -p ${HARBOR_PASSWORD}

# 2. 为镜像打标签
docker tag myapp:latest harbor.example.com/myapp/myapp:1.0.0
docker tag myapp:latest harbor.example.com/myapp/myapp:latest

# 3. 推送镜像
docker push harbor.example.com/myapp/myapp:1.0.0
docker push harbor.example.com/myapp/myapp:latest

# 4. 拉取镜像
docker pull harbor.example.com/myapp/myapp:1.0.0
```

Harbor 中的项目配置建议：

```
harbor.example.com/
  ├── library/              # 公共基础镜像（JDK、Nginx、Redis）
  ├── myapp-team/           # 团队项目
  │   ├── myapp-service     # 应用镜像
  │   ├── myapp-gateway     # 网关
  │   └── myapp-admin       # 管理后台
  └── thirdparty/           # 第三方镜像代理缓存
```

在 Kubernetes 中使用 Harbor 镜像时配置 `imagePullSecrets`：

```yaml
# 创建 Secret
kubectl create secret docker-registry harbor-secret \
  --docker-server=harbor.example.com \
  --docker-username=admin \
  --docker-password=${HARBOR_PASSWORD}

# 在 Deployment 中引用
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  template:
    spec:
      imagePullSecrets:
        - name: harbor-secret
      containers:
        - name: myapp
          image: harbor.example.com/myapp/myapp:1.0.0
```

```java
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock
    private OrderMapper orderMapper;

        // given
        OrderCreateRequest request = new OrderCreateRequest();
        request.setSkuId(1001L);
        request.setQuantity(2);
        request.setUserId(123L);

        when(inventoryClient.checkStock(1001L, 2)).thenReturn(true);
        when(orderMapper.insert(any(Order.class))).thenAnswer(invocation -> {
            Order order = invocation.getArgument(0);
            order.setId(1L);
            return 1;
        });

        // when
        Order result = orderService.createOrder(request);

        assertThat(result).isNotNull();
        assertThat(result.getId()).isEqualTo(1L);
        assertThat(result.getStatus()).isEqualTo(OrderStatus.PENDING);

        OrderCreateRequest request = new OrderCreateRequest();
        request.setSkuId(1001L);
        request.setQuantity(10);

        // when & then
        assertThrows(InsufficientStockException.class,
            () -> orderService.createOrder(request));

        request.setQuantity(quantity);

        assertThrows(IllegalArgumentException.class,
            () -> orderService.createOrder(request));
    }
```

冒烟测试在 CI/CD Pipeline 中的集成：

```yaml
# 在部署后自动执行冒烟测试
smoke-test:
  name: Smoke Test
  needs: deploy-dev
  runs-on: ubuntu-22.04
  steps:
    - name: Checkout
      uses: actions/checkout@v4

    - name: Wait for deployment to stabilize
      run: sleep 30

    - name: Run Smoke Tests
      run: |
        # 执行冒烟测试 Maven Profile
        ./mvnw test -Psmoke-test \
          -Dtarget.url=https://dev.myapp.example.com

    - name: Notify on Smoke Test Failure
      if: failure()
      run: |
        echo "Smoke tests failed! Rolling back deployment..."
        # 触发回滚
```

> **总结**：CI/CD 是现代软件工程的基础设施。GitHub Actions 适合中小团队和开源项目，YAML 语法简洁、与 GitHub 生态紧密集成；Jenkins Pipeline 适合企业级场景，灵活度高、插件生态丰富、与 K8s 集成成熟。无论采用哪种工具，都需要建立完整的编译-测试-分析-打包-部署流水线，同时通过 SonarQube 质量门禁、自动化测试和制品管理来保证交付质量。建议团队从 GitHub Actions 入门，随着规模增长逐步演进到 Jenkins + K8s 的企业级方案。
