# 用户权限与安全管理

## 一、用户管理

### 1.1 创建用户

```sql
-- 创建本地用户
CREATE USER 'dev_user'@'localhost' IDENTIFIED BY 'StrongP@ss123';

-- 创建远程用户（允许从任意主机连接）
CREATE USER 'app_user'@'%' IDENTIFIED BY 'StrongP@ss123';

-- 创建指定 IP 段用户
CREATE USER 'readonly'@'192.168.1.%' IDENTIFIED BY 'ReadP@ss123';

-- MySQL 8.0 推荐：使用 caching_sha2_password 插件（默认）
CREATE USER 'new_user'@'%' IDENTIFIED WITH caching_sha2_password BY 'password';

-- 兼容旧客户端：使用 mysql_native_password
CREATE USER 'legacy_user'@'%' IDENTIFIED WITH mysql_native_password BY 'password';
```

### 1.2 修改用户

```sql
-- 修改密码
ALTER USER 'dev_user'@'localhost' IDENTIFIED BY 'NewP@ss456';

-- 当前用户修改自己的密码
SET PASSWORD = PASSWORD('NewP@ss456');

-- 重命名用户
RENAME USER 'old_name'@'%' TO 'new_name'@'%';

-- 删除用户
DROP USER 'dev_user'@'localhost';

-- 查看所有用户
SELECT user, host, plugin FROM mysql.user;
```

### 1.3 密码策略（MySQL 8.0+）

```sql
-- 查看密码策略
SHOW VARIABLES LIKE 'validate_password%';

-- 设置密码策略
SET GLOBAL validate_password.policy = STRONG;     -- LOW/MEDIUM/STRONG
SET GLOBAL validate_password.length = 12;          -- 最小长度

-- 密码过期策略
ALTER USER 'app_user'@'%' PASSWORD EXPIRE INTERVAL 90 DAY;  -- 90 天过期
ALTER USER 'app_user'@'%' PASSWORD EXPIRE NEVER;              -- 永不过期

-- 密码历史（禁止重用最近 5 次密码）
ALTER USER 'app_user'@'%' PASSWORD HISTORY 5;
```

## 二、权限管理

### 2.1 权限层级

```
全局层级（*.*）
  └─ 数据库层级（mydb.*）
       └─ 表层级（mydb.users）
            └─ 列层级（mydb.users.email）
```

### 2.2 常用权限

| 权限 | 范围 | 说明 |
|:-----|:-----|:-----|
| `ALL PRIVILEGES` | 全局/数据库/表 | 所有权限（不含 GRANT OPTION） |
| `SELECT` | 全局/数据库/表/列 | 查询 |
| `INSERT` | 全局/数据库/表/列 | 插入 |
| `UPDATE` | 全局/数据库/表/列 | 更新 |
| `DELETE` | 全局/数据库/表/列 | 删除 |
| `CREATE` | 全局/数据库/表 | 创建库/表 |
| `DROP` | 全局/数据库/表 | 删除库/表 |
| `INDEX` | 全局/数据库/表 | 创建/删除索引 |
| `ALTER` | 全局/数据库/表 | 修改表结构 |
| `EXECUTE` | 全局/数据库 | 执行存储过程/函数 |
| `PROCESS` | 全局 | 查看所有连接（SHOW PROCESSLIST） |
| `REPLICATION SLAVE` | 全局 | 主从复制（从库需要） |
| `REPLICATION CLIENT` | 全局 | 查看主从状态 |

### 2.3 GRANT 与 REVOKE

```sql
-- 授予数据库级权限
GRANT SELECT, INSERT, UPDATE, DELETE ON mydb.* TO 'app_user'@'%';

-- 授予表级权限
GRANT SELECT ON mydb.users TO 'readonly'@'%';

-- 授予列级权限
GRANT SELECT (id, username, email) ON mydb.users TO 'limited'@'%';

-- 授予所有权限（生产慎用）
GRANT ALL PRIVILEGES ON mydb.* TO 'admin'@'%';

-- 带 GRANT OPTION（允许该用户授权给其他人）
GRANT SELECT ON mydb.* TO 'admin'@'%' WITH GRANT OPTION;

-- 撤销权限
REVOKE INSERT, UPDATE ON mydb.* FROM 'app_user'@'%';

-- 查看用户权限
SHOW GRANTS FOR 'app_user'@'%';

-- 刷新权限（GRANT/REVOKE 后通常自动刷新）
FLUSH PRIVILEGES;  -- 仅在直接修改 mysql 表时需要
```

## 三、角色（MySQL 8.0+）

MySQL 8.0 引入了角色功能，方便批量管理权限：

```sql
-- 创建角色
CREATE ROLE 'app_read', 'app_write', 'app_admin';

-- 给角色授权
GRANT SELECT ON mydb.* TO 'app_read';
GRANT INSERT, UPDATE, DELETE ON mydb.* TO 'app_write';
GRANT ALL PRIVILEGES ON mydb.* TO 'app_admin';

-- 把角色赋给用户
GRANT 'app_read' TO 'dev_user'@'localhost';
GRANT 'app_read', 'app_write' TO 'app_user'@'%';

-- 设置默认角色（用户连接时自动激活）
SET DEFAULT ROLE ALL TO 'dev_user'@'localhost';

-- 查看角色
SELECT * FROM mysql.role_edges;

-- 激活角色
SET ROLE 'app_read';
SET ROLE ALL;  -- 激活所有已分配角色

-- 撤销角色
REVOKE 'app_write' FROM 'app_user'@'%';

-- 删除角色
DROP ROLE 'app_read';
```

## 四、权限最小化原则

### 4.1 不同场景的权限建议

| 场景 | 建议权限 | 禁止权限 |
|:-----|:---------|:---------|
| **应用连接** | `SELECT, INSERT, UPDATE, DELETE`（指定库） | `DROP, ALTER, CREATE, GRANT` |
| **只读查询** | `SELECT`（指定库或表） | 所有写权限 |
| **备份用户** | `SELECT, LOCK TABLES, SHOW VIEW, EVENT, TRIGGER` | `DROP, ALTER, INSERT` |
| **主从复制** | `REPLICATION SLAVE`（全局） | 其他所有权限 |
| **监控用户** | `PROCESS, REPLICATION CLIENT, SELECT`（performance_schema） | 写权限 |

### 4.2 实践检查清单

```
□ 应用程序不使用 root 账户连接数据库
□ 应用账户只有业务所需数据库的 SELECT/INSERT/UPDATE/DELETE 权限
□ 不同环境（dev/staging/prod）使用不同账户
□ 密码使用强密码策略（12位以上，含大小写+数字+特殊字符）
□ 不在 SQL 语句中硬编码密码（使用环境变量或配置中心）
□ 定期审查用户权限，清理不再使用的账户
□ 开启 general_log 或 audit log 审计敏感操作
```

## 五、SQL 注入防护

### 5.1 常见注入攻击

```sql
-- 原始查询
SELECT * FROM users WHERE username = '$input' AND password = '$pwd';

-- 恶意输入：input = ' OR 1=1 --
-- 变成：
SELECT * FROM users WHERE username = '' OR 1=1 --' AND password = '';
-- 结果：绕过认证，返回所有用户
```

### 5.2 防护措施

**1. 参数化查询（最重要）**

```java
// Java 预编译语句（PreparedStatement）
String sql = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, username);
ps.setString(2, password);
ResultSet rs = ps.executeQuery();
```

```python
# Python 参数化查询
cursor.execute("SELECT * FROM users WHERE username = %s AND password = %s", (username, password))
```

**2. 存储过程**

```sql
CREATE PROCEDURE login(IN p_username VARCHAR(50), IN p_password VARCHAR(255))
BEGIN
  SELECT * FROM users WHERE username = p_username AND password = p_password;
END;
```

**3. 输入验证**

```python
import re
# 白名单验证：只允许字母数字
if not re.match(r'^[a-zA-Z0-9_]+$', username):
    raise ValueError("非法用户名")
```

**4. 最小权限**

```sql
-- 应用账户禁止执行动态 SQL
-- 不授予 ALTER、CREATE、DROP 权限
-- 禁止 FILE 权限（防止 LOAD_FILE / INTO OUTFILE 攻击）
```

## 六、SSL 连接配置

```sql
-- 查看 SSL 状态
SHOW VARIABLES LIKE '%ssl%';
SHOW STATUS LIKE 'Ssl_cipher';

-- 强制用户使用 SSL 连接
ALTER USER 'app_user'@'%' REQUIRE SSL;

-- 或 REQUIRE X509（要求客户端提供证书）
ALTER USER 'app_user'@'%' REQUIRE X509;

-- 服务端配置（my.cnf）
[mysqld]
ssl-ca = /etc/mysql/ssl/ca.pem
ssl-cert = /etc/mysql/ssl/server-cert.pem
ssl-key = /etc/mysql/ssl/server-key.pem
require_secure_transport = ON  -- 强制所有连接使用 SSL
```

```bash
# 客户端连接时指定 SSL
mysql -u app_user -p --ssl-ca=/path/to/ca.pem --ssl-cert=/path/to/client-cert.pem --ssl-key=/path/to/client-key.pem
```
