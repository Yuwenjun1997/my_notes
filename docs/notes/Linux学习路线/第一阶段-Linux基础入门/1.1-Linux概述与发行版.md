# Linux 概述与发行版

## 一、Linux 是什么

### 1.1 Linux 内核与 GNU 项目

Linux 严格来说只是**内核（Kernel）**，负责管理硬件资源（CPU、内存、磁盘、网络）。我们日常使用的"Linux 系统"实际上是 **GNU/Linux**——Linux 内核 + GNU 工具链（shell、编译器、核心工具等）。

```text
┌──────────────────────────────────────┐
│          用户应用程序                  │
├──────────────────────────────────────┤
│      Shell (bash/zsh) / GUI          │  ← 用户接口
├──────────────────────────────────────┤
│      GNU 核心工具 (coreutils)         │  ← ls, cp, cat, grep...
├──────────────────────────────────────┤
│      Linux 内核 (Kernel)              │  ← 硬件抽象、进程调度、内存管理
├──────────────────────────────────────┤
│      硬件 (CPU / 内存 / 磁盘 / 网络)    │
└──────────────────────────────────────┘
```

### 1.2 Linux 的优势

| 特性 | 说明 |
|:-----|:-----|
| **开源免费** | GPL 许可证，源码开放，无授权费用 |
| **稳定性** | 服务器可运行数年不重启 |
| **安全性** | 权限模型严格，病毒/恶意软件少 |
| **灵活性** | 高度可定制，从嵌入式到超算均可运行 |
| **生态丰富** | 几乎所有服务器软件优先支持 Linux |
| **社区强大** | 遇到问题有大量文档和社区支持 |

## 二、主流发行版对比

Linux 发行版（Distribution）= Linux 内核 + 包管理器 + 桌面环境 + 预装软件的组合。

### 2.1 发行版家族关系

```text
                    Debian                    Red Hat             独立
                      │                         │                  │
              ┌───────┼───────┐          ┌──────┼──────┐       Arch Linux
              ▼               ▼          ▼             ▼           │
           Ubuntu          Raspbian   RHEL          Fedora     Manjaro
              │                     (商业版)       (社区版)
      ┌───────┼───────┐
      ▼       ▼       ▼
   Kubuntu  Xubuntu  Linux Mint
```

### 2.2 主流发行版对比

| 发行版 | 包管理器 | 特点 | 适用场景 |
|:-------|:---------|:-----|:---------|
| **Ubuntu** | apt (deb) | 用户友好、文档丰富、社区活跃、LTS 长期支持 | **首选**：开发、服务器、桌面 |
| **Debian** | apt (deb) | 极其稳定、保守的软件版本 | 生产服务器 |
| **CentOS Stream** | dnf (rpm) | RHEL 的上游滚动版 | 企业级服务器（替代旧 CentOS） |
| **Rocky Linux** | dnf (rpm) | RHEL 兼容的社区版 | CentOS 迁移首选 |
| **Fedora** | dnf (rpm) | 新技术试验场，更新快 | 桌面开发 |
| **Arch Linux** | pacman | 滚动更新，高度定制 | Linux 进阶玩家 |
| **Alpine** | apk | 极致轻量（~5MB） | Docker 容器镜像 |

### 2.3 为什么选 Ubuntu？

对 Java 后端开发者而言，Ubuntu 是最佳选择：

- **LTS 版本**：每两年发布一次长期支持版（如 22.04、24.04），提供 5 年安全更新
- **软件丰富**：apt 仓库软件数量最大，PPA 扩展生态完善
- **文档最多**：遇到问题搜索 "ubuntu + 关键词" 几乎总能找到解决方案
- **云原生标准**：AWS/Azure/GCP 默认推荐 Ubuntu 镜像
- **桌面体验好**：GNOME 桌面 + Ubuntu 定制，对 Windows 迁移用户友好

## 三、Ubuntu 版本管理

### 3.1 版本号规则

Ubuntu 版本号格式：`YY.MM`（发布年份.月份）

```text
Ubuntu 20.04 LTS  →  2020年4月发布，长期支持
Ubuntu 22.04 LTS  →  2022年4月发布，长期支持
Ubuntu 24.04 LTS  →  2024年4月发布，长期支持
Ubuntu 23.10      →  2023年10月发布，非LTS（9个月支持）
```

### 3.2 LTS vs 非 LTS

| 对比维度 | LTS（长期支持版） | 非 LTS |
|:---------|:-----------------|:-------|
| 发布周期 | 每 2 年 | 每 6 个月 |
| 支持期限 | 5 年（Ubuntu Pro 可到 10 年） | 9 个月 |
| 软件版本 | 较稳定（偏旧） | 较新 |
| 服务器推荐 | ✅ 强烈推荐 | ❌ 不推荐 |
| 桌面推荐 | ✅ 推荐 | 尝鲜用户 |

> ⚠️ **注意事项**：生产环境务必使用 LTS 版本，非 LTS 仅适合体验新特性。

### 3.3 当前推荐版本

- **服务器**：Ubuntu 24.04 LTS 或 Ubuntu 22.04 LTS
- **桌面开发**：Ubuntu 24.04 LTS
- **WSL2 学习**：Ubuntu 24.04 LTS

## 四、常用 Linux 术语速查

| 术语 | 说明 |
|:-----|:-----|
| **内核（Kernel）** | 操作系统的核心，管理硬件与进程 |
| **发行版（Distribution）** | 内核 + 软件包集合 + 包管理器的组合 |
| **Shell** | 命令行解释器，用户与内核交互的桥梁 |
| **终端（Terminal）** | 运行 Shell 的窗口程序 |

| **仓库（Repository）** | 软件包的远程存储服务器 |
| **Root** | 超级用户，拥有系统最高权限 |
| **守护进程（Daemon）** | 后台运行的服务进程 |

## 五、进阶：版本识别、内核解读与心智模型

### 5.1 /etc/os-release：脚本里判断发行版的标准姿势

```bash
cat /etc/os-release
# NAME="Ubuntu"
# VERSION="24.04.1 LTS (Noble Numbat)"
# ID=ubuntu
# VERSION_ID="24.04"
# VERSION_CODENAME=noble
# ID_LIKE=debian
# PRETTY_NAME="Ubuntu 24.04.1 LTS"

# 脚本里取关键字段（比解析 lsb_release 更通用）⭐
. /etc/os-release && echo "发行版: $ID $VERSION_ID, 代号: $VERSION_CODENAME"

# 判断发行版系，决定用 apt 还是 dnf/yum
. /etc/os-release
case "$ID_LIKE" in
  debian) echo "用 apt" ;;
  rhel)   echo "用 dnf/yum" ;;
esac
```

> 💡 `/etc/os-release` 被几乎所有主流发行版支持，是纯文本键值对，脚本里 `source` 它即可拿到稳定的 ID/版本号——运维脚本判断环境的通用做法。

### 5.2 内核版本号逐段解读

```bash
uname -a
# Linux hostname 6.8.0-31-generic #31-Ubuntu SMP PREEMPT_DYNAMIC x86_64 GNU/Linux
#       ①主机名   ②内核版本          ③构建信息             ④架构
```

| 段 | 含义 |
|:---|:-----|
| `6` | 主版本号（大版本演进） |
| `8` | 次版本号（功能新增；**奇数=开发版，偶数=稳定版**） |
| `0` | 修订号（补丁/修复） |
| `31` | Ubuntu 自有的补丁号 |
| `generic` | 内核风味：generic（通用）、lowlatency（低延迟）、server |
| `x86_64` | CPU 架构 |

```bash
uname -r      # 只显示内核版本
uname -m      # 只显示架构
uname -s      # 内核名（Linux）
```

### 5.3 Ubuntu 版本代号规律

```bash
lsb_release -a        # 发行版全信息
lsb_release -c        # 只看代号
lsb_release -r        # 只看版本号
```

> 💡 Ubuntu 代号规律：**形容词 + 动物名**，按字母序递增：20.04 `focal` → 22.04 `jammy` → 24.04 `noble`。**换 apt 源时"代号"必须和系统匹配**（1.2 §3 的坑）——用 `lsb_release -c` 或 `/etc/os-release` 的 `VERSION_CODENAME` 确认，别照抄网上的旧代号。

### 5.4 Linux vs Windows 心智模型对比

| 维度 | Windows | Linux | 迁移要点 |
|:-----|:--------|:------|:---------|
| 盘符 | `C:` `D:` | 一个根 `/`，设备挂到目录下（`/home`、`/data`） | 没有盘符概念，看 `/` |
| 路径分隔 | `\` | `/` | 大小写敏感：`File.txt` ≠ `file.txt` |
| 软件安装 | 双击 .exe | 包管理器 `apt install` | 装软件先 `apt update` |
| 权限 | 管理员/UAC | 每个文件有 owner/group/others + rwx | `sudo` 临时提权 |
| 换行符 | `\r\n` (CRLF) | `\n` (LF) | 文件传 Windows 后可能出现 `^M`（**2.7 cat -A**） |
| 服务 | 服务管理器 | systemd + systemctl | 开机自启用 `systemctl enable` |

### 5.5 术语速查扩展

在第四节速查表基础上补充三类高频术语：

| 术语 | 说明 | 关联笔记 |
|:-----|:-----|:---------|
| **进程 / 线程** | 进程=独立内存空间的运行实例；线程=进程内共享内存的执行单元 | **2.4 进程管理** |
| **标准流** | stdin(0) / stdout(1) / stderr(2)，每个进程默认的三条数据通道 | **2.1 §5 重定向** |
| **文件描述符 fd** | 进程打开文件/网络的整数句柄；`lsof`/`/proc/PID/fd` 查看 | **4.3 §2 lsof** |

> 💡 术语表不仅是背单词，更是后续学习的**索引**：遇到陌生词回这里看它属于哪条知识线。

## 📝 实践项目

### 目标

了解 Ubuntu 版本信息，熟悉发行版相关操作。

### 步骤

1. **查看当前系统信息**
   ```bash
   uname -a
   lsb_release -a
   cat /etc/os-release
   ```

2. **查看内核版本**
   ```bash
   cat /proc/version
   hostnamectl
   ```

3. **了解系统架构**
   ```bash
   arch          # 查看 CPU 架构（x86_64 / aarch64）
   dpkg --print-architecture   # 查看包架构
   ```

4. **浏览 Ubuntu 官网**
   访问 https://ubuntu.com/download 了解最新 LTS 版本
